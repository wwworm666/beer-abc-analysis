# Явные связи iiko и Untappd

## Что это

Реестр **GUID внутреннего товара iiko → числовой ID пива Untappd**.
Название, артикул, транслитерация и URL-slug не являются ключом связи.
Задача: связать реальную номенклатуру кег для достоверного таплиста,
сохранив различия версий, сладости и производителей.

Проход 20.09.2026 расширен на **все 479 карточек кег**, включая архивные,
удалённые и не использовавшиеся за последние два года:

- 462 имеют решение `verified`; 11 неразрешённых, 5 пропущенных, 1 техническая позиция исключена;
- все 233 позиции с движением за 20.09.2024–20.09.2026 включительно связаны;
- охват продаж этих позиций — 100%;
- последние три связи предоставлены владельцем напрямую, включая исправление производителя Dopamine на Zavod.

`verified` означает проверку связи по доступным источникам или уточнению
владельца, а не физическую сверку каждой поставленной кеги. Отсутствие
карточки в результатах поиска не доказывает отсутствие пива в Untappd.

**Интеграция:** код V2 использует этот реестр через GUID товара на кране.
Старые записи мигрируются только по однозначному локальному имени и артикулу;
спорные позиции уточняются на странице. См. [taplist-v2.md](taplist-v2.md).
Production-выкладка отдельно от изменения кода; `/menu` и справочник бота не менялись.

## Как работает (с примерами и формулами)

### Поиск кандидатов и явное решение

1. Входной набор берётся из `keg-register.json`. Артикул вспомогательный:
   в iiko он может повторяться у блюд и товаров.
2. Исторические `beer_info_mapping.json`, `menu_new_sorts.json` +
   `menu_newsorts_output.json`, `menu_research_input.json` +
   `menu_research_output.json` дают только кандидатов. Нормализация для
   поиска: NFKC, регистр, ё/е, пунктуация, удаление «КЕГ» и фасовки.
   Слова сладости, рецептуры и версии сохраняются. Fuzzy-порога нет.
3. Кандидаты сверяются с публичными карточками и уточнениями. Правила
   «одна найденная ссылка = подтверждённая связь» нет.
4. Решение вносится явно по GUID. `verified` требует конкретной карточки,
   числового ID, причины и даты. Пересборка исторических подсказок не меняет
   решение. Прежние отклонённые ID сохраняются для аудита.
5. Для `needs_identity`, `needs_variant`, `needs_source` внешняя связь
   остаётся `null`. Отсутствие решения означает `candidate`/`unresearched`.
   `candidate_urls` сохраняет найденную точную ссылку даже при недоступных
   метаданных карточки: это не повышает её до проверенной связи.

### Использование связи

```python
from core.untappd_registry import load_registry, resolve_beer

registry = load_registry()
card = resolve_beer(registry, iiko_product_id)
```

Функция принимает GUID и проверяет статус, согласованность решения/карточки,
ID, домен и путь источника, свидетельство. Возвращает копию карточки или
`None`. Неизвестный GUID, имя, артикул, кандидат или испорченная связь дают
`None`; запасного поиска по похожему имени нет. Импорт не выполняет I/O;
вызывающий код явно загружает и обновляет снимок. Ошибка загрузки файла
не подменяется старым fuzzy-поиском.

Несколько GUID могут вести на один внешний ID: разные фасовки/локальные
карточки одного сорта. После уточнений 462 GUID ведут на 436 ID.
Здесь так связаны два Schrader и Rewort Shade of
Summer / Mahatma G. Заголовок карточки `2367269` прямо перечисляет прежние
названия. При этом показатели в снимках менялись: 7,3%/48 IBU и 6,5%/25 IBU.
Последний выбранный снимок не описывает автоматически прошлую партию.

Артикул может совпадать даже у разных кег: `64157` принадлежит архивному
Radeberger и актуальному Eibauer, `00213` — Kona Big Wave и La Branche.
Связи по GUID сохраняют разные сорта; неопределённый La Branche не получает
карточку Kona. Удалённая карточка с названием «1» остаётся без связи:
для неё нужны сведения о товаре, а не расширенный поиск по похожим словам.

Если один GUID используется для разных рецептур, глобальная связь
недостаточна. Например, Static Cloud найден с разными хмелями и крепостью;
до уточнения партии связь закрыта. Для интеграции потребуется отдельная
карточка товара на рецепт либо явный выбор версии при подключении партии.
Нельзя молча выбрать последнюю найденную версию.

### Характеристики и свежесть

Показатели берутся из прочитанной карточки. Неизвестное — `null`, не ноль
и не среднее по стилю. ABV хранится в процентных пунктах (`4.6` = 4,6%).
`observed_at` — дата проверки; `source_crawl` — доступный возраст поискового
снимка, иногда относительный. Это разные сведения: дата проверки не делает
старый снимок свежим. В изменившихся карточках выбранный текущий снимок
сопровождается предыдущими наблюдениями для повторной проверки.
Для «Лось и Кедр V.3.0» метаданные прочитаны в записи публичного каталога
Untappd, а ID — из её ссылки. Метод и ссылка каталога записаны отдельно;
страницу подробностей получить не удалось. Для «Кислого движа» доступен
снимок возрастом 1,8 года. У Swinckels заголовок показывает 5,3%, описание
5%; в реестре сохранён показатель заголовка и отмечено расхождение.
Рейтинги, изображения и полные описания в эту итерацию не включены.
Автоматическое обновление Untappd не настроено.

### Охват и воспроизводимость

Охват = сумма литров списаний по продажам проверенных GUID / сумма таких
литров всех 233 приоритетных GUID × 100.

`57 605,675 / 57 605,675 × 100 = 100,00%`.

Суммы вычисляются десятичными числами без промежуточного округления.
Процент — два знака, HALF_UP. При нулевом знаменателе результат `null`.
Товары без продаж дают 0 литров, но остаются в количестве позиций. Это
охват исторических продаж в литрах, не выручки и не текущих кранов.
Количественный охват — отдельная метрика: 233 из 233 с движением,
462 из 479 во всей номенклатуре. `all_status_counts` считает все карточки,
`recent_status_counts` — только с движением. `verified_beers` считает
уникальные внешние ID во всём реестре, `recent_verified_beers` — в недавнем
ассортименте. Добавление архива не меняет знаменатель исторических продаж.

Сборка: `python scripts/build_untappd_registry.py` из корня проекта.
При одинаковых входах JSON/CSV побайтно воспроизводимы; часы и сеть не
используются. Дата/период закреплены на этом снимке; для нового среза нужны
новая выгрузка и явное обновление конфигурации. Хеши охватывают снимок,
исходные товары, решения, наблюдения и пять исторических файлов.

### Использование в веб-сервисе

V2 передаёт GUID из подсказки через состояние крана в строгую функцию чтения.
Сведения о миграции, ручном уточнении, CSV и встроенном реестре Docker:
[taplist-v2.md](taplist-v2.md). Для обновления связей изменяются решения и
наблюдения, затем выполняется сборка реестра. Подмены по похожему имени нет.
