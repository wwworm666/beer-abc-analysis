# Таплист V2

## Что это

Кнопка «Таплист V2» скачивает CSV текущих кранов с проверенными характеристиками
Untappd. С 20.09.2026 код использует явную связь GUID товара iiko → ID Untappd.
462 из 479 товаров связаны; все 233 товара с движением за последние два года
имеют проверенную связь. Это охват справочника, а не обещание, что все старые
записи кранов уже содержат GUID. Выкладка на production — отдельный шаг.

## Файлы

- `routes/taps.py` — выбор товара, уточнение старого крана, JSON и CSV.
- `core/taps_manager.py` — сохранение GUID, миграция и актуальное чтение кранов.
- `core/taplist.py` — каталог, однозначная миграция локальной идентичности,
  единая проекция JSON/CSV.
- `core/untappd_registry.py` — строгая проверка связи и карточки.
- `resources/iiko_untappd_registry.json` — проверенные связи и характеристики.
- `templates/taps_bar.html` — выбор кеги, характеристики, уточнение сорта.
- `Dockerfile` — включение справочника в образ вне изменяемого тома данных.
- `tests/test_taplist_v2.py`, `tests/test_untappd_registry.py` — регрессии.
- `docs/research/taplist-v2-mapping-audit.json` — аудит прежнего алгоритма.

## Как работает (с примерами и формулами)

### Выбор и хранение

`GET /api/beers/draft` возвращает отдельную запись на каждый GUID, даже при
одинаковых названиях или артикулах. Основой служит реестр кег; локальная
номенклатура добавляет варианты локального имени и новые товары с префиксом
«КЕГ » / «KEG ». Техническая исключённая карточка не попадает в выбор.

При выборе мышью или Enter браузер запоминает GUID и отправляет
`iiko_product_id` в START/REPLACE. Любая последующая правка текста сбрасывает
выбор и артикул; требуется повторно выбрать подсказку. Сервер проверяет GUID
и согласованность выбранного имени. Старые API-клиенты могут по-прежнему
передать только имя, но характеристики из похожего названия не подбираются.

Кран хранит `iiko_product_id` отдельно от `current_keg_id`: последний исторически
содержит артикул либо AUTO-номер и не является уникальным товаром. GUID
сохраняется в событиях подключения/замены/остановки. При замене старый GUID
не наследуется, при остановке очищается.

### Уже подключённые кеги

При чтении страницы или V2 под файловой и потоковой блокировкой выполняется
идемпотентная миграция. Ищется точное локальное имя iiko (удаляются только
внешние пробелы). Если сохранён артикул, он также обязан совпасть. При AUTO-
номере достаточно единственного точного имени. Только один кандидат даёт GUID.
Нормализация, транслитерация, сопоставление по одному артикулу и сравнение
с названием Untappd не применяются. Уже сохранённый GUID не переопределяется.

Миграция сохраняет `product_identity.origin=legacy_exact_name_article`, не меняет
время подключения, имя, номер кеги и историю. При неоднозначности кран остаётся
в таплисте с отметкой «Уточните сорт на кране» и пустыми характеристиками.

Кнопка «Уточнить сорт для таплиста» позволяет выбрать товар для уже подключённой
кеги без фиктивной замены. `POST /api/taps/<bar_id>/identify` принимает GUID,
номер крана и прежние `current_beer`, `current_keg_id`, `started_at`,
`iiko_product_id` в `expected`. Если кран успел измениться, возвращается 409.
Сохраняются прежнее время и история; источник выбора — `manual_selection`.

### Характеристики и выгрузка

`GET /api/taps/taplist-full` и `/api/taps/export-taplist-full` строятся из одного
снимка и одной функции. Каждый запрос перечитывает актуальный файл кранов:
изменение другим процессом сервера видно сразу. Ошибки чтения/сохранения больше
не выдаются за успешную операцию. Ошибка загрузки реестра даёт 503, запасного
подбора из `beer_info_mapping.json` нет. Неизвестный бар даёт 404.

Например, локальное «КЕГ Bumblebeer Dopamine» через подтверждённый GUID ведёт
к Zavod Dopamine (3636325). Название пивоварни в iiko не используется как
основание для замены подтверждённой связи. Два разных Rustiq по сладости
сохраняют разные ID.

JSON содержит исходное имя, GUID, Untappd ID/URL, пивоварню, название, стиль,
ABV, IBU, описание, дату проверки, `mapped`, `mapping_status`, `mapping_message`.
`mapped_count` считает только проверенные связи. Для неизвестных значений
возвращается `null`; в CSV — пустая ячейка. ABV 6.2 означает 6,2%, нулевой IBU
остаётся нулём. Характеристики не вычисляются по стилю.

CSV: UTF-8 с BOM, запятая, все поля в кавычках. Первые девять колонок сохранены:
бар, кран, пивоварня, название, Untappd URL, стиль, ABV, IBU, описание. Добавлены
исходное имя iiko и статус связи. Имена баров совпадают со страницами.
Потенциальные формулы в текстовых полях экранируются апострофом.
`X-Taplist-Unmapped-Count` сообщает число строк без проверенной связи.

Параметр `bar_id` ограничивает бар; по умолчанию включены активные непустые
краны. `active_only=false` включает также неактивные записи с именем.
Каждый кран даёт отдельную строку, даже если на нескольких один сорт.

Отсутствующие описания, рейтинги и изображения не придумываются. Автоматического
обновления Untappd нет: используется проверенный снимок с датой. Некоторые
источники получены из более раннего поискового снимка; детали в
[untappd-links.md](untappd-links.md). Связь не гарантирует характеристики каждой
будущей партии, если под одним GUID начинают продавать другую рецептуру.

### Развёртывание

Docker копирует проверенный реестр в `/app/resources/iiko_untappd_registry.json`.
Том `/srv/beer/data:/app/data` не скрывает его. Приоритет загрузки:
`UNTAPPD_REGISTRY_PATH` (если явно задан), встроенный resources-файл, затем
локальный `data/iiko_untappd_registry.json` (совместимость). Повреждённый выбранный файл не
подменяется другим. Для обновления встроенного реестра нужен новый образ.

Перед выкладкой сохранить резервную копию рабочего `taps_data.json` по
фактическому пути менеджера (обычно `/kultura/taps_data.json` в контейнере).
Не переносить в production локальный снимок кранов. При первом чтении V2
произойдёт описанная выше безопасная миграция; неоднозначные позиции будут
видны на странице. Бот со своим старым справочником и независимый `/menu`
этой интеграцией не переключаются.

## Changelog

- 2026-09-20 — V2 подключён к проверенному реестру по GUID. Добавлены
  сохранение идентичности, однозначная миграция, ручное уточнение без смены
  кеги, актуальное чтение между процессами и явные ошибки хранения.
  Исправлены Enter, сохранение старого артикула после редактирования и
  небезопасная вставка названий в HTML. JSON/CSV используют одну проекцию.
  Ошибка здесь приводит к характеристикам чужого сорта; регрессии проверяют
  расхождения названий, дубли артикулов, неизвестные версии и сбой хранения.
- 2026-09-20 — Предварительный аудит выявил подмены сладости, версий и
  производителей при нормализации и fuzzy matching. Машинный аудит сохранён.

Проверка реализации: 26 автоматических тестов и проверка интерфейса в браузере
пройдены. Перед публикацией все 26 тестов повторно прошли поверх актуального main.
Публикация в main запускает workflow `Deploy production`: общие тесты проекта,
затем обновление сервера через настроенный ключ GitHub Actions. Фактический
результат выкладки проверяется по этому workflow; локальная проверка сама по себе
не подтверждает обновление production.
