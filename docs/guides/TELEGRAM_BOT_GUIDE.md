## Команды

| Команда | Описание |
|---------|----------|
| `/start` | Кнопки баров |
| `/taplist` | Меню выбора бара (кнопки) |
| `/taplist1` | Большой пр. В.О |
| `/taplist2` | Лиговский |
| `/taplist3` | Кременчугская |
| `/taplist4` | Варшавская |
| `/taplistall` | Все бары |
| `/subscribe` | Подписаться на новости (подписанному — изменить бары) |
| `/review` | Оставить отзыв |
| `/stop` | Отписаться от новостей (`/unsubscribe` — то же) |

Команды бот забирает сам (`core/taplist_polling.py`, long-polling `getUpdates`).
Входящий webhook Telegram до сервера не доходит, а отзыв токена в BotFather
ещё и стирает сохранённый webhook. `TAPLIST_POLLING=0` выключает приём.
`/telegram/setup-webhook` с polling спорит: следующий ответ 409 снимает webhook обратно.

В личном чате под кнопками баров в меню ещё две кнопки: «Подписаться на новости»
(у подписанного — «Отписаться от новостей») и «Оставить отзыв» — **когда владелец включил
их** на странице контент-плана («Каналы и отправка» -> «Кнопки подписки и отзывов в боте»,
настройка `bot.signup`, по умолчанию выключено). В группах меню — только краны: подписка и
отзыв работают лишь в личном чате.

## Подписка на новости и отзывы (с 2026-09-28)

### Что это

Гость подписывается на новости и акции баров прямо в @kult_taplist_bot — с явным
согласием, выбором баров и (по желанию) телефоном. Рассылки делает контент-план
(канал «Бот», `docs/content-plan.md`): он берёт получателей по аудитории из
`core/guest_subscribers.py`. Там же гость может оставить отзыв — он попадает на
страницу «Отзывы» рядом с отзывами Яндекс Карт.

### Файлы

| Файл | Что делает |
|------|-----------|
| `core/taplist_polling.py` | Диалог бота: кнопки, согласие, бары, телефон, `/stop`, отзыв. План (`plan_update`) — чистая функция, исполнение — `_execute` |
| `core/guest_subscribers.py` | База подписчиков `guest_subscribers.db`, текст согласия с версией, телефон и связка с базой гостей, аудитории рассылки, API для отправителя |
| `core/guest_reviews.py` | Хранилище отзывов (сюда бот пишет отзыв) |
| `tests/test_guest_subscribers.py` | База, согласие, отписка, блокировка, аудитории на границах дней |
| `tests/test_taplist_polling.py` | План диалога и исполнение с поддельным Telegram (сети нет) |

### Как проходит подписка

1. «Подписаться на новости» (или `/subscribe`, или ссылка `?start=subscribe`) — бот
   присылает текст согласия и кнопки «Согласен» / «Не сейчас». До «Согласен» о госте
   ничего не записывается.
2. «Согласен» — гость подписан: в базе время согласия и **версия текста согласия**
   (`CONSENT_VERSION`; сам текст — в `CONSENT_TEXTS` в коде). Менять формулировку —
   только новой версией, старые не удалять: по ним видно, на что соглашался каждый.
   Версия зашита и в кнопку (`sub_agree:<версия>`): «Согласен» под старым текстом не
   подписывает — бот показывает текущий текст заново.
3. Выбор баров: можно отметить несколько (отмеченные — с «✓») или «Все бары».
   Ничего не отмечено или отмечены все четыре = «Все бары» (так в подписку попадёт и
   новый бар сети). Сохраняется по «Готово».
4. Телефон — по желанию: кнопка Telegram «Поделиться телефоном» (Telegram сам
   подтверждает, что номер свой; чужой контакт и номер, набранный текстом, не
   принимаются) или «Пропустить».
5. «Готово: вы подписаны…» — с напоминанием, как отписаться.

Отписка — кнопка «Отписаться от новостей» или `/stop`: подписка снимается, **телефон и
связка с гостем стираются** — и в подписке, и в отзывах гостя из бота; время согласия и
отписки остаются как запись. Об отписавшемся новые данные (имя, ник) не копятся.

### Телефон и база гостей

Российский номер хранится в том же каноне, что и гость в `guests.db`
(`core/guest_sync.normalize_guest_id`): 10 цифр с 9, 11 цифр с 7 или 8, 12 цифр с 77 (лишняя
7 из iiko, см. `docs/guests.md`) -> `'7' + последние 10`. Так «+7 999…», «8 999…» и `779…`
совпадают. В контакте Telegram номер всегда с кодом страны: российский — только 7 и 10 цифр.
**Зарубежный номер** хранится как есть (`+` и цифры), с гостем не связывается и в аудиториях
«были / не были» не участвует: раньше армянский 37477123456 становился чужим казахстанским
+77477123456 с привязкой к чужой карте гостя. По российскому телефону ищется гость:
`guests.guest_id`, затем `guests.phone` (при нескольких — с последним визитом), затем
псевдоним `guest_aliases`. Не нашёлся — не ошибка, подписка работает и так.

### Аудитории рассылки

Всегда — только подписанные и не заблокировавшие бота. Если у рассылки выбран бар, её
получают только отметившие этот бар или «Все бары» (гость сам выбрал, новости каких баров
получать) — для любой аудитории.

| Аудитория | Кто получит |
|-----------|-------------|
| `bot_all` — все подписчики | все подписчики |
| `bot_bar` — выбравшие бар | отметившие бар или «Все бары»; бар обязателен |
| `bot_recent_30` — были за 30 дней | последний визит в любой бар сети — не раньше 29 дней назад (30 дней, включая сегодня). Сегодня 28.09 — визиты с 30.08 по 28.09 |
| `bot_lapsed_60` — не были 60 дней | последний визит 60 и больше дней назад. Сегодня 28.09 — визит 30.07 или раньше |

Визит 30–59 дней назад — ни в одной из двух. Без телефона (или если гость по телефону не
нашёлся) подписчик в «были / не были» **не попадает**. Визиты — по базе гостей, она
обновляется ночью: сегодняшних визитов в расчёте нет.

Гость заблокировал бота — Telegram сообщает сразу (`my_chat_member`), а при рассылке
отвечает 403 (отправитель зовёт `mark_blocked`): рассылка ему не уходит, пока он снова
не напишет боту или не разблокирует его.

### Отзыв через бота

«Оставить отзыв» (или `/review`) -> бар -> оценка 1–5 -> текст одним сообщением или
«Отправить без текста» -> «Спасибо». Отзыв сохраняется в `core/guest_reviews`:

| Поле | Значение |
|------|----------|
| `source` / `origin` | `bot` / `import` (на странице его можно удалить — по просьбе гостя или как спам; меню карточки, с подтверждением) |
| `external_id` | `tg:<chat_id>:<message_id>` — сообщение гостя с текстом; без текста — сообщение бота с кнопкой. Повтор того же сообщения — «уже сохранён», дубля нет |
| `created_at` | время сообщения по Москве (без текста — момент нажатия) |
| `author` | имя и фамилия из профиля Telegram |
| `guest` | `telegram`: `@ник` или chat id; `phone`: `+7…`, только если гость подписан и делился телефоном |
| `added_by` | «Бот @kult_taplist_bot» |

- Ждём текст 30 минут; шаг хранится в базе подписчиков, поэтому перезапуск воркера
  (--max-requests, деплой) набранный отзыв не теряет. Позже 30 минут — «время вышло», текст
  не сохраняется (иначе «привет» на следующий день стал бы отзывом). Любая команда прерывает
  отзыв. На любой текст, которого бот не ждёт, он отвечает подсказкой (/start, /review), а не
  молчит.
- Не больше **3 отзывов из одного чата за московские сутки** (`REVIEW_DAILY_LIMIT`), не
  больше 20 уведомлений владельцу об отзывах из бота в час (дальше — сводкой); спам удаляется
  на странице отзывов.
- Владелец узнаёт о новом отзыве **сразу**: после сохранения бот в фоновом потоке
  отправляет его подписчикам бота kulturaopenclosed (`core/review_notify.notify_review_now`,
  отметка `tg_notified_at`). Бот персонала открыт для подписки, поэтому туда уходят **только
  бар, оценка, дата и ссылка** — без имени, ника, телефона и текста. Пропущенные (перезапуск,
  не было подписчиков, потолок) бот сам подбирает раз в 10 минут; сверка Яндекса для этого не
  нужна. `YANDEX_REVIEWS_NOTIFY=0` выключает и эти отправки ([yandex-reviews.md](../yandex-reviews.md)).
- **Ответ гостю.** На странице «Отзывы» владелец сохраняет ответ и нажимает «Отправить гостю
  в Telegram» (с подтверждением): гость получает от бота «Ответ бара «<бар>» на ваш
  отзыв:» и текст. Если Telegram не ответил, а сообщение могло дойти, — «статус неизвестен»,
  повтор только отдельной кнопкой после проверки у гостя. Гость заблокировал бота — ответ не
  уходит, подписчик отмечается заблокировавшим. Подробности — [reviews.md](../reviews.md),
  «Ответ гостю в Telegram».
- Текст гостя хранится как есть (данные): бот отвечает без разметки, страница отзывов и
  уведомления экранируют текст сами.

### Выключатель «Кнопки подписки и отзывов в боте»

Бот спрашивает `core.content_channels.bot_signup_enabled()` на каждый апдейт — включение
действует без перезапуска. Нет настройки, файла или любой сбой — выключено.

| Выключено (по умолчанию) | Включено |
|---|---|
| меню — только краны; подписанному гостю остаётся «Отписаться от новостей» (её обещает текст согласия) | + «Подписаться на новости» / «Отписаться от новостей» и «Оставить отзыв» |
| `/subscribe`, `/review`, ссылки `?start=subscribe`, `?start=review…` и старые кнопки «Подписаться» / «Оставить отзыв» открывают меню кранов | ведут в подписку и отзыв |
| `/stop` и «Отписаться» работают | то же |
| начатый при включённом шаг (согласие, бары, телефон, оценка, текст отзыва) можно закончить — «Согласен» и кнопки отзыва принимаются только из ЖИВОГО шага этого чата (не старше 30 минут); старые и подделанные кнопки ведут в меню | — |
| меню команд Telegram (`setMyCommands`) — без `/subscribe` и `/review` | с ними |

Меню команд бот сверяет с выключателем не чаще раза в минуту и переотправляет при смене.
Включать — когда утверждён текст согласия. Рассылки — отдельный выключатель («Рассылки
гостям»): можно собирать подписчиков, ещё ничего не рассылая.

### Как устроено внутри

- `plan_update(update, dialog, signup)` превращает апдейт в список действий без сети и
  базы; `handle_update` берёт состояние диалога и выключатель, строит план и исполняет его.
- Кнопки несут всё в `callback_data` (выбор баров — маска `sb:<маска>:<действие>`,
  отзыв — `rv:…`, «Согласен» — `sub_agree:<версия>`). Шаг диалога (согласие показано,
  выбор бара или оценки, ждём текст или телефон) — в таблице `dialogs` базы подписчиков
  (`PersistentDialogStore`, таймаут 30 минут); база не отвечает — шаг держится в памяти.
- Раз в минуту цикл опроса сверяет выключатель с меню команд, раз в 10 минут запускает
  подбор пропущенных уведомлений об отзывах (`Housekeeping`).
- API для отправителя рассылок: `audience_size(segment, bar)`, `recipients(segment, bar)`,
  `mark_blocked(chat_id)`, `stats()` — подробности в докстринге `core/guest_subscribers.py`.
- Проверка без Telegram: `py -3 -m pytest -q tests/test_guest_subscribers.py tests/test_taplist_polling.py`.

### Этап 4: Fuzzy Matching при запросе

**Файл:** `telegram_webhook.py` → `find_beer_info_local()`

Когда пользователь запрашивает `/taplist`, происходит:

```
1. Получить краны из taps_manager
         │
         ▼
2. Для каждого крана с пивом:
   beer_name = "КЕГ Бланш де Намур, светлое"
         │
         ▼
3. Нормализация названия:
   - Убрать "КЕГ "
   - Убрать ", светлое"
   - Убрать объёмы (30 л)
   - Заменить тире на пробел
   Результат: "бланш де намур"
         │
         ▼
4. Поиск в mapping:
   a) Точное совпадение после нормализации
   b) Fuzzy match (difflib.SequenceMatcher)
   c) Порог ≥ 75% = совпадение
         │
         ▼
5. Найдено: "Бланш де Намур" → {brewery, style, abv, untappd_url}
         │
         ▼
6. Форматирование ответа для Telegram
```

## Алгоритм Fuzzy Matching

```python
def normalize(name):
    """Нормализует название для сравнения"""
    name = name.lower()
    name = name.replace('кег ', '')                    # КЕГ
    name = name.replace(' — ', ' ').replace('-', ' ')  # Тире
    name = name.replace(',', '').replace('.', '')      # Пунктуация
    name = re.sub(r'\d+\s*(л|l|кг|kg|ml|мл)', '', name) # Объёмы
    # Суффиксы
    for suffix in ['светлое', 'темное', 'нефильтрованное', ...]:
        name = name.replace(suffix, '')
    return ' '.join(name.split()).strip()

def similarity(a, b):
    """difflib.SequenceMatcher"""
    return SequenceMatcher(None, a, b).ratio()

# Поиск
threshold = 0.75  # 75%
for key in mapping:
    score = similarity(normalize(beer_name), normalize(key))
    if score >= threshold:
        return mapping[key]  # Найдено!
```

**Примеры:**
```
"КЕГ Бланш де Намур, светлое" → "бланш де намур" → "Бланш де Намур" ✓
"КЕГ Гулден Драк 708, 20 л"   → "гулден драк 708" → "Гулден Драк 708 20 л" ✓
"Бюльви — Рустик полусухой"   → "бюльви рустик"  → "Бюльви Рустик полусухой" ✓
```

## Webhook настройка

> Сейчас бот работает через long-polling (`core/taplist_polling.py`), webhook не нужен:
> установленный webhook polling снимет сам (ответ 409). Команды ниже — справочно.
> `<TOKEN>` — токен бота из `.env` (`TELEGRAM_BOT_TOKEN`); в документы его не вписывать.

### Установка webhook (один раз)

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://www.beerkultura.ru/telegram/webhook"
```

### Проверка статуса

```bash
curl "https://api.telegram.org/bot<TOKEN>/getWebhookInfo"
```

### Удаление webhook (для локальной разработки)

```bash
curl "https://api.telegram.org/bot<TOKEN>/deleteWebhook"
```

После удаления можно запустить `telegram_bot.py` в polling режиме.

## Локальная разработка

> Не запускайте бота локально с боевым токеном: пока прод забирает апдейты (polling),
> второй `getUpdates` с тем же токеном получает 409 и отнимает сообщения гостей у прода.
> Для опытов заведите отдельного тестового бота в @BotFather.

```bash
# 0. Логику подписки и отзывов можно проверить вообще без Telegram
py -3 -m pytest -q tests/test_guest_subscribers.py tests/test_taplist_polling.py

# 1. Снять webhook ТЕСТОВОГО бота (<TOKEN> — его токен, не боевой)
curl "https://api.telegram.org/bot<TOKEN>/deleteWebhook"

# 2. Запустить настоящий polling-цикл бота (краны, подписка, отзывы) с токеном тестового бота.
#    Подписчики и отзывы пишутся в локальные data/guest_subscribers.db и data/guest_reviews.json.
#    (Старый telegram_bot.py умеет только краны — подписки и отзывов в нём нет.)
TELEGRAM_BOT_TOKEN=<TOKEN> py -3 -c "import time; from core import taplist_polling as t; t.start_polling(); time.sleep(10**9)"

# 3. Тестировать бота
```

## Переменные окружения

| Переменная | Значение |
|------------|----------|
| `TELEGRAM_BOT_TOKEN` | токен бота — только в `.env`, в документы не вписывать (старое значение из этого файла — в локальном `secrets/LOCAL_NOTES.md`, раздел «TELEGRAM_BOT_GUIDE») |
| `TAPLIST_POLLING` | `0` — не забирать апдейты (бот молчит); по умолчанию включено |

## Логи и отладка

В логах приложения на сервере (`docker compose logs app`) искать:

```
[TAPLIST-POLL] справочник пива: 408
[TAPLIST-POLL] polling стартовал, бот @kult_taplist_bot
```

При ошибках:
```
[TAPLIST-POLL] update failed: ...          апдейт не разобрался (очередь идёт дальше)
[TAPLIST-POLL] sendMessage fail chat=...    Telegram не принял сообщение (код и причина рядом)
[TAPLIST-POLL] sub_agree failed: ...        сбой шага подписки или отзыва; гостю ушло «Что-то пошло не так»
[TAPLIST-POLL] отзыв не сохранён: ...       файл отзывов не читается — гостю «попробуйте позже»
[GUEST-SUBS] витрина гостей не читается     телефон сохранён без связки с гостем
```
