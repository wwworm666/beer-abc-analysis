# Настройка экспорта ЗП в Google Таблицу

## Что это

Кнопка «Экспорт Google» на `/salary` записывает расчёт месяца **вкладкой в
Google Таблицу** — теми же строками и формулами, что и `.xlsx`. Отличие от
Excel-выгрузки: Таблицы считают формулы на сервере, поэтому цифры видны сразу,
без «пустых ячеек в предпросмотре».

Код готов и задеплоен. Чтобы кнопка заработала, нужен **ключ сервис-аккаунта
Google** — это единственный шаг, который делается руками в Google Cloud
Console. API-ключа недостаточно: запись в Таблицы требует учётной записи, а
сервис-аккаунт — единственный вариант без интерактивного входа человека.

Пока ключа нет, кнопка отвечает «Экспорт в Google Таблицу не настроен» и
ничего не ломает — `.xlsx` работает как работал.

## Часть 1. Google Cloud Console (~5 минут, делается один раз)

### 1. Создать проект

1. Открыть <https://console.cloud.google.com/>
2. Вверху слева выпадающий список проектов -> **Создать проект**
3. Имя: `beer-kultura` (любое) -> **Создать**
4. Дождаться создания и **выбрать** этот проект в том же списке

### 2. Включить Sheets API и Drive API

1. Меню -> **API и сервисы** -> **Библиотека**
2. Найти **Google Sheets API** -> **Включить**
3. Вернуться в Библиотеку, найти **Google Drive API** -> **Включить**
   (нужен, только если экспорт будет создавать новые таблицы; если пишем в
   существующую — можно пропустить)

### 3. Создать сервис-аккаунт

1. Меню -> **API и сервисы** -> **Учётные данные**
2. **Создать учётные данные** -> **Сервисный аккаунт**
3. Имя: `beer-salary-export` -> **Создать и продолжить**
4. Роль не выбирать (права на таблицу выдаются шарингом, а не ролью IAM) ->
   **Продолжить** -> **Готово**

### 4. Скачать JSON-ключ

1. В списке учётных данных нажать на созданный сервис-аккаунт
2. Вкладка **Ключи** -> **Добавить ключ** -> **Создать ключ** -> **JSON** ->
   **Создать**
3. Файл скачается сам. Это и есть ключ — **никому не пересылать и не
   коммитить в git**
4. Там же скопировать **email сервис-аккаунта** — вида
   `beer-salary-export@beer-kultura.iam.gserviceaccount.com`

### 5. Расшарить таблицу бухгалтерии

1. Открыть таблицу, в которую должны попадать вкладки месяцев
2. **Настройки доступа** -> вставить email сервис-аккаунта из шага 4
3. Права — **Редактор** -> **Отправить**
   (галочку «Уведомить» можно снять — это робот)
4. Скопировать **id таблицы** из адресной строки — длинная строка между
   `/d/` и `/edit`:
   `https://docs.google.com/spreadsheets/d/`**`1AbC...XyZ`**`/edit`

## Часть 2. Сервер (делается один раз)

Положить ключ на VPS и прописать две переменные:

```bash
# 1. Скопировать скачанный JSON на сервер (выполнять на своём компьютере)
scp ~/Downloads/beer-kultura-*.json root@139.100.200.92:/srv/beer/secrets/google-sa.json

# 2. Дальше — на сервере
ssh root@139.100.200.92
mkdir -p /srv/beer/secrets && chmod 700 /srv/beer/secrets
chmod 600 /srv/beer/secrets/google-sa.json

# 3. Прописать переменные окружения
cd /opt/beer
echo 'GOOGLE_SA_JSON=/app/secrets/google-sa.json' >> .env
echo 'SALARY_SHEET_ID=<id таблицы из шага 5>'      >> .env

# 4. Примонтировать папку с ключом в контейнер: в docker-compose.yml
#    в секцию volumes сервиса app добавить строку
#      - /srv/beer/secrets:/app/secrets:ro

# 5. Перезапустить
docker compose up -d --build app
```

Проверка, что контейнер видит ключ:

```bash
docker exec beer-app python -c "from core.salary_gsheet import _load_credentials; \
  print('сервис-аккаунт:', _load_credentials().service_account_email)"
```

## Как пользоваться

1. `/salary` -> выбрать месяц -> **Рассчитать**
2. **Экспорт Google** -> откроется вкладка таблицы с расчётом

Вкладка называется по месяцу — «июль2026», рядом с остальными листами
бухгалтерии.

**Повторный экспорт того же месяца** спросит подтверждение: перезапись сотрёт
то, что бухгалтер заполнил в этой вкладке руками — «мосты», «Отпуск», «Доп
доход», «Вычет инвент», «Доп вычет». Приложение эти строки не ведёт и
восстановить их не может, поэтому молча не перезаписывает.

Каждый экспорт пишется в журнал графика (`salary_gsheet_export`) — видно, кто
и когда выгружал.

## Переменные окружения

| Переменная | Обязательна | Смысл |
|---|---|---|
| `GOOGLE_SA_JSON` | да | Путь к JSON-ключу в контейнере (по умолчанию `/app/secrets/google-sa.json`) |
| `GOOGLE_SA_JSON_CONTENT` | нет | Ключ строкой вместо файла (альтернатива монтированию) |
| `SALARY_SHEET_ID` | нет | id целевой таблицы. Пусто — каждый экспорт создаёт **новую** таблицу |
| `SALARY_SHEET_FOLDER_ID` | нет | Папка Drive для новых таблиц (когда `SALARY_SHEET_ID` пуст) |

## Если что-то не работает

| Сообщение | Причина | Что делать |
|---|---|---|
| «Экспорт в Google Таблицу не настроен» / «Нет ключа сервис-аккаунта» | Ключа нет по пути или папка не примонтирована | Часть 2, шаги 1–4 |
| «Не установлены библиотеки Google API» | Образ собран до появления зависимостей | `docker compose up -d --build app` |
| `SERVICE_DISABLED` / «Google Sheets API has not been used in project ...» | В проекте не включён Sheets API. Частый случай: проект заведён автоматически под Gemini/AI Studio (имя вида `gen-lang-client-…`) — там включён только Generative Language API | Открыть ссылку из текста ошибки (`console.developers.google.com/apis/api/sheets.googleapis.com/overview?project=<номер>`) -> **Включить**, подождать 1–2 минуты |
| «Таблица ... недоступна» | Таблица не расшарена на сервис-аккаунт | Часть 1, шаг 5, права **Редактор** |
| Вкладка уже существует | Месяц уже выгружали | Подтвердить перезапись или переименовать старую вкладку |

Доступность Google API с прода проверена 2026-08-01 (ТСПУ его не режет, в
отличие от Telegram — см. `docs/open-check-bot.md`).
