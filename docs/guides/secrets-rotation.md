# Обновление секретов

## Что сменить прямо сейчас

Репозиторий **публичный** (`visibility: public`, форки разрешены), то есть всё
отслеживаемое читает кто угодно, а история остаётся доступной и после правки
файла. Разбор 21.09.2026 нашёл в нём четыре набора рабочих учётных данных.
Значения из файлов убраны, но **это не защита**: кто скопировал репозиторий
раньше, знает их. Защита — смена значения у сервиса.

| Что | Где лежало | Чем грозит | Смена |
|---|---|---|---|
| Токен бота Telegram | `docs/guides/TELEGRAM_BOT_GUIDE.md` | Управление ботом | Сделано 21.09.2026 |
| Пароль администратора MeshCentral (`admin`) | `MESHcentral_INSTALLATION_COMPLETE.md`, две инструкции в `MeshCentral-Agent-Install/`; там же адрес сервера | **Удалённое управление бар-ПК** | Нужна |
| Пароль и логин iiko API | `docs/technical/CODE_ANALYSIS_COMPLETE.md`, `docs/archive/PROJECT_OVERVIEW.md`; сервер известен из `config.py` | Все данные бизнеса: продажи, сотрудники, цены | Нужна |
| Пароли бар-ПК: `sshuser`, Администратор, RDP-пользователь | `docs/CONNECTIVITY.md`, `docs/remote-sync.md`, `chz_test/README.md`, `docs/CHANGELOG.md` | Вход на машины в барах | Нужна |

Порядок для каждой строки — раздел «Если секрет успели увидеть посторонние».
Отдельно стоит решить, должен ли репозиторий оставаться публичным: пока он
публичен, любая будущая ошибка такого рода видна сразу всем.

## Что это

Пошаговая замена секрета (токен бота, пароль, ключ) с ноутбука на Windows.
Написано для случая «токен засветился, завёл новый, надо подставить».

Секрет живёт в двух местах, и они не равны по важности:

| Где | Зачем | Что сломается без него |
|---|---|---|
| `/opt/beer/.env` на сервере | **Источник истины.** Подключается через `env_file` в `docker-compose.yml`, приложение читает env при старте контейнера | Функция просто выключается: бот молчит, интеграция не работает |
| GitHub → Secrets → Actions | Копии для workflow, которым секрет нужен в CI | Красный workflow. На работу сайта и бота не влияет |

Значение не вставляют: в переписку и чаты, в файлы репозитория, в команду целиком
(PowerShell пишет историю на диск в `ConsoleHost_history.txt`, bash — в `~/.bash_history`),
в скриншоты. Правило проверяется тестом `tests/test_no_committed_secrets.py`.

## Файлы

- `.env.example` — список всех переменных проекта без значений.
- `docker-compose.yml` — `env_file: .env`, раздел `app`.
- `.github/workflows/telegram-webhook.yml` — единственный workflow, которому нужен
  `TELEGRAM_BOT_TOKEN`.
- `.github/workflows/deploy.yml` — использует `BEER_DEPLOY_SSH_KEY` и
  `BEER_DEPLOY_KNOWN_HOSTS`, их настройка описана в [deploy.md](deploy.md).

## Как работает

### Шаг 1. Получить новое значение

Для бота Telegram: написать [@BotFather](https://t.me/BotFather) → `/mybots` →
выбрать бота → **API Token** → **Revoke current token**. Старый перестаёт работать
сразу, новый показывается на экране. Не пересылать его никуда — он понадобится
ровно два раза, оба через буфер обмена.

### Шаг 2. Сервер — от этого зависит работа

Открыть **PowerShell** (кнопка Пуск → набрать `powershell` → Enter) и подключиться:

```powershell
ssh root@139.100.200.92
```

Дальше команды выполняются уже на сервере. Открыть файл с секретами:

```bash
nano /opt/beer/.env
```

Если `nano` не установлен: `apt install -y nano` и повторить.

Внутри редактора:

1. Стрелками найти строку `TELEGRAM_BOT_TOKEN=` (поиск: `Ctrl+W`, ввести имя, Enter).
2. Встать в конец строки (`End`), стереть старое значение (`Backspace` до знака `=`).
3. Вставить новое: в PowerShell вставка идёт **правой кнопкой мыши**, не `Ctrl+V`.
4. Проверить глазами: `TELEGRAM_BOT_TOKEN=123456789:AA...`, без пробелов вокруг `=`,
   без кавычек, значение одной строкой.
5. Сохранить: `Ctrl+O`, Enter. Выйти: `Ctrl+X`.

Если строки с таким именем в файле нет — добавить её в конец файла.

Применить (env читается при создании контейнера, поэтому его надо пересоздать;
пересборка образа не нужна):

```bash
cd /opt/beer && docker compose up -d --no-build app
```

Проверить, что приложение поднялось и бот инициализирован:

```bash
docker compose logs --tail 30 app | grep -i telegram
```

Ожидаемая строка: `[TELEGRAM] Бот инициализирован (webhook режим)`. Если вместо неё
`[TELEGRAM] Ошибка инициализации бота` — значение испорчено при вставке (лишний
пробел, обрезанный хвост, кавычки), вернуться к `nano`.

Эта проверка ловит только испорченное значение: токен правильной формы, но чужой
или устаревший, приложение примет молча, а откажет уже Telegram при первом запросе.
Поэтому окончательная проверка — шаг 4.

Отключиться от сервера:

```bash
exit
```

### Шаг 3. GitHub Secret

В браузере открыть
[Settings → Secrets and variables → Actions](https://github.com/wwworm666/beer-abc-analysis/settings/secrets/actions).

- Секрет с таким именем уже есть → напротив него **Update**, вставить новое значение,
  **Update secret**. Старое значение посмотреть нельзя, это нормально.
- Секрета нет → **New repository secret**, имя вписать точно как в таблице ниже
  (регистр важен), вставить значение, **Add secret**.

### Шаг 4. Проверить

- **Бот**: написать ему в Telegram, он должен ответить.
- **Сайт**: открыть https://beerkultura.ru — страница входа отвечает.
- **Вебхук** (не обязательно, бот после `/revoke` остаётся тем же):
  [Actions → Telegram webhook](https://github.com/wwworm666/beer-abc-analysis/actions) →
  **Run workflow** → `getWebhookInfo`. Workflow виден только после слияния ветки с ним
  в `main`: `workflow_dispatch` подхватывается с ветки по умолчанию.

### Какие секреты где нужны

| Имя | Сервер `.env` | GitHub Secrets | Что отвечает |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | да | Бот таплиста; в GitHub — только для workflow «Telegram webhook» |
| `TELEGRAM_OPEN_CHECK_BOT_TOKEN` | да | нет | Проверка открытых смен в 14:59 МСК |
| `IIKO_LOGIN`, `IIKO_PASSWORD` | да | нет | Весь обмен с iiko: дашборд, остатки, цены таплиста |
| `ORDERIA_LOGIN`, `ORDERIA_PASSWORD` | да | нет | Вкладка «Не купившие» в разделе «Гости» |
| `REMOTE_PASS` | да | нет | Доступ к бар-ПК для «Честного знака» |
| `SECRET_KEY` | да | нет | Подпись сессий. Смена разлогинит всех |
| `BEER_DEPLOY_SSH_KEY`, `BEER_DEPLOY_KNOWN_HOSTS` | нет | да | Выкладка на прод, см. [deploy.md](deploy.md) |

### Если секрет успели увидеть посторонние

Порядок именно такой, удаление строки из файла — последний шаг, а не первый:

1. **Отозвать значение** у того, кто его выдал (@BotFather `/revoke`, панель провайдера,
   смена пароля). Пока значение действует, всё остальное бессмысленно.
2. Подставить новое по шагам выше.
3. Убрать значение из всех файлов, где оно осело, и прогнать
   `python -m pytest -q tests/test_no_committed_secrets.py`.
4. Историю git переписывать не нужно: отозванное значение безвредно, а `force-push`
   в `main` ломает все клоны и открытые PR.
