# Стандарт выбора периода

## Что это

Одно правило для всех страниц сайта, которые показывают данные за отрезок времени: на каком
периоде страница открывается, как выбирается период, как он подписан, где хранится, как
передаётся между страницами и как его понимает сервер.

Зачем (владелец, 2026-11-01): «Привести к одному стандарту выбор периода на всех страницах.
Лучшее — дашборд, но и у него есть недостатки». Поводом стал «Маркетинг»: 1 ноября он открылся
на пустом ноябре, а «Графики за» рядом с выбором периода читались как второй выбор периода.

Основа стандарта — шапка дашборда (лучший элемент на сайте), правило «Маркетинга» «открываться
там, где есть данные» и серверное «сегодня» по рабочим суткам бара (`core/msk_time`).

Статус: **утверждён владельцем 2026-11-01** (раздел «Решения владельца»). Переход — по фазам,
каждая отдельным PR (раздел «Переход»). Фазы 1–3 сделаны (ждут выкладки): серверный модуль периодов,
общий элемент «Период», дашборд на нём; бар — один ключ у дашборда и раздела «Гости».

## Как сейчас (инвентаризация 2026-11-01)

Девять разных элементов выбора на двух десятках страниц, у страниц разное «сегодня» и разные правила открытия.

| Страница | Как выбирается период | Открывается на | Помнит |
|---|---|---|---|
| Дашборд `/` | шапка: ‹ период ›, меню быстрого выбора, свой период (Flatpickr) | последней закрытой неделе | нет (только бар) |
| «Сравнение» (вкладка дашборда) | свои два списка недель | текущей неделе | нет |
| «Маркетинг» `/guests` | Неделя / Месяц / Квартал / Год и ‹ › | месяце последнего полного дня (с 2026-11-01) | нет (бар — `gh.bar`) |
| «Акции» (вкладка «Маркетинга») | два поля дат | 1 января — сегодня по часам устройства | нет |
| Конструктор `/explorer` | меню «Период»: 10 серверных пресетов + свои даты | прошлой неделе | да (черновик, `?report=`) |
| Розлив, фасовка, кухня | меню «Период»: пресеты (три копии кода) + свои даты | 30 дней по вчера по часам устройства | нет |
| Ежемесячный отчёт | список лет + список месяцев (ТОП-10) | текущем годе | нет |
| Зарплата `/salary` | календарь диапазона | прошлом месяце по часам устройства | нет |
| Сотрудники `/employee` | два календаря (анализ, сравнение) | прошлой неделе по часам устройства | нет |
| Цели `/goals` | поле месяца | текущем месяце по часам устройства | нет |
| График, чистота | ‹ месяц › | месяце по часам устройства | нет |
| Мои смены `/me` | выбора нет | текущем месяце | нет |
| Контент-план, отзывы | ‹ месяц › и меню | текущем месяце по Москве | `?month=` |
| Температура | 24 часа / 3 дня / 7 дней | 7 днях | нет |
| Краны, склад, сроки, меню | выбора нет: окно 7 / 30 / 105 дней | — | — |

Что не так (подробности с номерами строк — в отчётах инвентаризации, сводка здесь):
- **«Сегодня» считается пятью способами:** рабочие сутки по Москве (до 06:00), календарная дата
  по Москве, часы устройства, UTC (`date.today()` / `datetime.now()` в контейнере без часового
  пояса) и «часы устройства + 3 часа». В ночь на 1-е график, чистота и «Мои смены» открывают
  новый месяц, хотя идёт смена прошлого.
- **Восемь правил открытия:** прошлая неделя, текущая неделя, текущий месяц, прошлый месяц, 30
  дней, 1 января — сегодня, текущий год, месяц последнего полного дня. Ежемесячный отчёт в январе
  и «Маркетинг» 1-го числа открывались пустыми.
- **Период нигде не попадает в адрес страницы** (кроме контент-плана и отзывов): перезагрузка
  сбрасывает выбор, ссылкой период не передать. План «ссылки между страницами с
  `?date_from=&date_to=`» (`docs/planning/cross-page-connectivity.md`, механизм A) не сделан.
- **Неполный период не подписан** почти нигде: «эта неделя» молча включает неполный сегодняшний
  день; на дашборде «прошло N из M дней» видно только при наведении мыши.
- **«30 дней» — разные:** у розлива 30 дат по вчера, у сервера без дат — 31 дата по сегодня, у
  склада — 30 полных дней плюс неполный сегодняшний.
- **Зашитые пределы календаря:** сотрудники — 31.12.2026 (с 1 января 2027 года новые даты не
  выбрать), зарплата и дашборд — 31.12.2027, форма планов — 2025–2027 годы.
- **Выбор бара хранится в трёх разных местах** (дашборд, раздел «Гости», склад), на остальных
  страницах не хранится.

Недостатки дашборда (лучшего из существующих):
- нет года в названии недели и своего периода («Неделя 44» — какого года?);
- вкладка «Планы» молча меняет общий период на месяц и не возвращает неделю;
- «Сравнение» живёт отдельно от шапки и с ошибками: выбирает будущие недели, по воскресеньям не
  находит текущую (дата недели читается как UTC), «Год к году» не работает;
- клавиша → уводит в будущее, хотя кнопка › выключена;
- заметки к совещанию теряют текст, если сменить период за секунду после ввода;
- период не сохраняется в адресе, первые секунды в шапке «—»;
- календарь грузится с CDN, его предел зашит, подсказки о неполном периоде — только при наведении.

## Стандарт

### 1. «Сегодня» — одно: рабочие сутки бара по Москве, с сервера

- Учётный день — рабочие сутки бара: до 06:00 МСК идёт вчерашний день
  (`msk_time.business_today()`). Ночная смена 31-го — это ещё октябрь.
- Страница получает `today` и `last_full_day` (последний полный день данных) от сервера при
  открытии, в своём конфиге. Часы устройства для дат не используются: у сотрудника телефон может
  стоять в другом часовом поясе, а контейнер сервера живёт в UTC.
- Если вкладка браузера открыта долго, после 06:00 «сегодня» обновляется (по ответу сервера или
  при возврате на вкладку).
- Для дат в коде запрещены `date.today()`, `datetime.now()` без часового пояса и
  `new Date()` как «сегодня». Проверка по коду (кроме меток времени событий) появится в фазе 8,
  когда уйдут нынешние такие места.

### 2. Одна модель периода

- Период — это `date_from` и `date_to`, обе даты **включительно**, формат `YYYY-MM-DD`, в
  учётных днях. Переход к «правая граница не включается» — только внутри клиента iiko.
- Шаги: день, неделя (ISO, понедельник — воскресенье), месяц, квартал, год и свой период. Шаг
  определяется по границам: 1–31 октября — месяц, понедельник — воскресенье — неделя; иначе —
  свой период.
- Скользящее окно «Последние N дней» — ровно N учётных дней, последний из них — последний полный
  день (обычно вчера). Не N + 1 и не «по сегодня».
- Состояние периода: **закрыт** (весь в данных), **идёт** (кончается позже последнего полного
  дня; цифры по `cutoff`), **будущий** (начинается позже — данных нет).

### 3. На каком периоде открывается страница

У каждой страницы — одно из трёх правил (таблица «Страницы»):

| Правило | Для каких страниц | Пример на 20 октября |
|---|---|---|
| **Последний закрытый** период основного шага | отчёты: дашборд, «Маркетинг», ежемесячный отчёт, сотрудники, зарплата | неделя 12–18 окт; месяц — сентябрь |
| **Текущий** период (идёт) | рабочие страницы: график, чистота, мои смены, цели, контент-план, отзывы | октябрь (с пометкой «идёт») |
| **Последние N дней** | ABC/XYZ: розлив, фасовка, кухня; конструктор — прошлая неделя | 20 сентября — 19 октября |

- Ссылка с периодом в адресе сильнее правила (раздел 6).
- Страница никогда не открывается на будущем или пустом периоде. Если данных за период нет
  (например, синк отстал), открывается период, где лежит последний полный день, и это видно в
  подписи.

### 4. Элемент «Период» — один на сайте

Вид — шапка дашборда, но с исправленными недостатками. В закрытом виде одна строка:

```
[‹]  [календарь  Октябрь 2026 · идёт, по 29.10  ▾]  [›]
```

- **Название — всегда с годом:** «Октябрь 2026», «III квартал 2026», «2026», неделя — «26 окт –
  1 ноя 2026» (номер недели мельче), свой период — «12 – 25 окт 2026».
- **Неполный период подписан текстом** «идёт, по 29.10» — и на телефоне. Подсказки только при
  наведении не используются.
- **Стрелки** шагают на один период текущего шага. › выключена на текущем периоде (кроме страниц,
  где планируют вперёд: график, контент-план, цели). Клавиши ← → ведут себя как стрелки и не
  обходят ограничения.
- **Панель** (по нажатию на название; на телефоне — лист снизу):
  1. Шаг: День · Неделя · Месяц · Квартал · Год — только шаги, которые есть у страницы.
     Недоступный шаг не показывается; если его надо объяснить — причина видна текстом.
  2. Сетка периодов выбранного шага: недели списком с датами, месяцы — сеткой года с выбором
     года, кварталы, годы. Периоды без данных выключены.
  3. Быстрый выбор (страница выбирает свой набор из общего списка): «Последний закрытый»,
     «Текущий», «Последние 7 / 30 / 90 / 180 дней», «С начала месяца», «С начала года».
  4. «Свой период» — календарь диапазона внутри панели (два месяца на компьютере, один на
     телефоне), можно ввести даты вручную. Пределы — первый день данных и последний полный день,
     а не зашитая дата.
  5. Внизу — свежесть данных: «Данные по 31.10 · обновлено 31.10, 08:10 МСК».
- **Смена шага** берёт период нового шага, где лежит конец текущего (у неполного — последний
  полный день). Из октября (по 29.10) в недели — неделя 26 окт – 1 ноя, а не неделя 1-го числа.
- **Применяется сразу:** выбор в списке и шаг стрелкой — без кнопки «Применить»; свой период —
  после второй даты.
- **Доступность:** кнопки не меньше 44 px на телефоне, подписи для экранного диктора, Esc
  закрывает панель и возвращает фокус на кнопку.

### 5. Где стоит

- На каждой странице с данными — одна полоса под заголовком: `[Бар ▾] [‹ Период ▾ ›] …
  [свежесть данных] [выгрузка]`, в том же порядке и том же виде, что на дашборде.
- Переключатели, которые меняют вид, а не период (порог оттока, «Графики за», шаг графика),
  стоят у того блока, который меняют, и подписывают результат («Динамика по месяцам: ноя 24 —
  окт 26»). Рядом с выбором периода их не ставят — иначе они читаются как второй выбор периода.
- Вкладки одной страницы пользуются общим периодом. Вкладка, которой нужен другой шаг (например,
  «Планы» — только месяц и год), показывает подпись и предлагает шаг, но не меняет общий период
  молча. Отдельный набор полей дат внутри вкладки («Акции», «Сравнение») не делается: тот же
  элемент.

### 6. Адрес страницы, переходы и бар

- **Бар — один на весь сайт** (решение владельца 2026-11-01): выбрал Лиговский на любой
  странице — все страницы открываются на Лиговском, пока не сменишь. Хранится в браузере под
  одним ключом `kultura.bar` (ключ заведения: `bolshoy`, `ligovskiy`, `kremenchugskaya`,
  `varshavskaya`; пусто — вся сеть). Старые ключи (`dashboard_selected_venue`, `gh.bar`,
  `stocks.bar`) читаются один раз при переходе страницы на стандарт. `?bar=` в адресе сильнее.
- **Период между страницами не переносится** (решение владельца): обычный переход по меню
  открывает страницу по её правилу; ссылка из одной страницы в другую передаёт период явно.
- Период и бар — в адресе: `?date_from=2026-10-01&date_to=2026-10-31&bar=ligovskiy`. Адрес
  меняется при каждом выборе (`history.replaceState`), поэтому перезагрузка и скопированная
  ссылка открывают тот же период. Кнопка «Назад» браузера по периодам не шагает.
- Ссылки между страницами передают период и бар явно (так задуманы переходы в
  `docs/planning/cross-page-connectivity.md`): из карточки дашборда в «Розлив» — тот же период.
- Неверный период в адресе — страница открывается по своему правилу и пишет: «Период из ссылки
  не распознан — показан …».

### 7. Неполный и будущий период

- У идущего периода все цифры — по `cutoff`, подпись «идёт, по 29.10».
- Сравнение с прошлым периодом у идущего — равной длины: 1–29 окт против 1–29 сен. План — по
  дням с весами, как на вкладке «Выручка» дашборда (лучший образец сейчас).
- На графиках идущий период отмечается (пустая точка, пунктир) или не рисуется, если число ещё
  растёт (отток). Под графиком — «Последняя точка: …», как на «Оттоке».
- Будущий период (только из ссылки или на страницах планирования) — подпись и кнопка «Открыть
  последний период с данными».

### 8. Сравнение

- Один вид для всех страниц: «Сравнить с: прошлым периодом · тем же периодом год назад · своим
  периодом». Первый период — всегда выбранный в шапке; отдельных списков недель нет.
- У идущего периода сравнение — равной длины (раздел 7).

### 9. Окна без выбора

- Страницы с постоянным окном (склад и заказы — 30 дней, краны — 7 дней, сроки годности) не
  получают элемент выбора, но подписывают окно датами: «за 30 дней: 2–31 окт».
- Окно — ровно N дней, последний — последний полный день (раздел 2).

### 10. Сервер

- Один модуль периодов (`core/periods.py`): разбор параметров, границы, шаг по границам,
  подписи, состояние, `cutoff`, «сегодня» по рабочим суткам. Существующие
  `guest_analytics.resolve_period`, `olap_constructor` (пресеты), `weeks_generator` переходят
  на него.
- Все маршруты принимают `date_from` и `date_to`. Старые параметры (`period_type` + `anchor`,
  `month`, `days`, `period1_key`) живут как синонимы, пока не переведены страницы и инструменты
  агентов.
- В ответе — `meta.period`: `key`, шаг, `date_from`, `date_to`, название, короткое название,
  состояние, `cutoff`. Страница берёт подписи отсюда — один источник вместо шести форматов дат.

### 11. Инструменты агентов (MCP)

- Основной параметр — `date_from` и `date_to` по тем же правилам; старые остаются синонимами.
- Описание инструмента ссылается на этот стандарт. При переводе маршрута — правка схемы
  инструмента (правило проекта: тесты сверяют схему с маршрутом).

## Переход

Каждая фаза — отдельный PR с тестами и документацией; выкладка — с согласия владельца.

0. **Срочно, независимо от стандарта:**

## Решения владельца

Приняты 2026-11-01:
1. Отчёты открываются на **последнем закрытом** периоде (как дашборд), текущий — стрелкой вперёд,
   с пометкой «идёт».
2. Выбранный период **не переносится** между страницами при обычном переходе: каждая открывается по
   своему правилу, ссылки передают период явно.
3. Выбор бара — **один на весь сайт** (раздел 6).
4. Начать с фаз 1–3: серверный модуль, общий элемент, дашборд.

## Файлы

Стандарт (фазы 1–2, 2026-11-01):

| Файл | Что делает |
|---|---|
| `core/periods.py` | Сервер: `Period` (шаг, `date_from`/`date_to` включительно, ключ, название, `to_meta`), `period_for`, `from_bounds` (шаг по границам), `shift`, `last_closed`, `current`, `last_days`, состояние и `cutoff`, подписи, `parse_period` (`date_from`/`date_to`, синоним `key`; ошибка — `PeriodError` → 400), `page_config(live, last_full_day, data_start)` |
| `static/js/shared/period/period_core.js` | Страница: то же, что сервер (`window.KPeriod`), плюс часы страницы `configure(page_config)`, быстрый выбор `QUICK`, адрес `readUrlPeriod` / `writeUrlPeriod` |
| `static/js/shared/period/period_picker.js` | Элемент «Период» (`window.KPeriodPicker.mount`) |
| `static/js/shared/period/scope.js` | Бар на весь сайт (`window.KScope.getBar` / `setBar`, ключ `kultura.bar`, `?bar=`) |
| `static/shared/period.css` | Стили элемента: компьютер — выпадающая панель, телефон — лист снизу |
| `tests/fixtures/period_labels.json` | Общие примеры подписей, состояний и правил открытия — по ним проверяются и сервер, и страница |
| `tests/test_periods.py`, `tests/test_period_core.mjs` | Тесты сервера и ядра страницы |

Как подключить страницу (фазы 4–8):
1. Маршрут кладёт в шаблон `period_config=periods.page_config(...)`: живые данные iiko — `live=True`;
   витрина с ночной загрузкой — `live=False, last_full_day=..., data_start=...`.
2. Шаблон: `period.css`, затем обычными скриптами `period_core.js`, `scope.js`, `period_picker.js` и
   `KPeriod.configure(window.<PAGE>_PERIOD)` — до скриптов страницы.
3. Страница: начальный период — `KPeriod.readUrlPeriod()` или правило открытия (`KPeriod.lastClosed(шаг)`,
   `KPeriod.currentPeriod(шаг)`, `KPeriod.lastDays(N)`), затем
   `KPeriodPicker.mount(контейнер, {steps, quick, value, allowFuture, urlSync: true, freshness, onChange})`.
   Методы: `get()`, `set(period, {silent})`, `setSteps(steps, причина)`, `destroy()`.
4. Запросы — `date_from` и `date_to` выбранного периода; сервер разбирает их `periods.parse_period`.

Пока не переведены: `static/js/guests/common.js` («Маркетинг»), `static/js/explorer/page.js`,
`static/js/draft/draft.js`, `static/js/packaging/packaging.js`, `static/js/kitchen/kitchen.js`,
`static/js/schedule/common.js`, `templates/{bonus,employee,goals,monthly_report}.html` и др. (таблица
«Как сейчас»); сервер — `core/guest_analytics.resolve_period`, `core/olap_constructor.py` (пресеты),
`core/weeks_generator.py`.
