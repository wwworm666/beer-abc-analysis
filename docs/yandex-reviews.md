# Отзывы Яндекс Бизнеса — загрузка в «Отзывы» (`core/yandex_business.py`)

> Этап 1 (2026-09-28): сверка раз в сутки загружает отзывы четырёх баров в «Отзывы».
> Только чтение кабинета: ответить на отзыв или удалить что-либо в Яндексе сервис не может.
> Постановка задачи — [апи яд](апи%20яд) (файл владельца в `docs/`).

## Что это

Отзывы с Яндекс Карт должны сами появляться на странице «Отзывы» ([reviews.md](reviews.md)),
а не вноситься руками. Публичного API отзывов у Яндекс Бизнеса нет. Кабинет владельца
(`yandex.ru/sprav`) сам получает их из своего JSON API, и сервис делает то же самое с сессией
аккаунта, у которого есть доступ к организациям.

План по этапам:

| Этап | Что | Состояние |
|---|---|---|
| 0 | Клиент кабинета + диагностика на реальных данных: наши ли филиалы, их `permanent_id`, формат отзыва, пагинация | готово, проверено 2026-09-28 |
| 1 | Сверка в `guest_reviews.json` раз в сутки: история, ответы организации, пропавшие отзывы, строка состояния на странице | код готов 2026-09-28, на проде не включён |
| 2 | Ответ из сервиса прямо в Яндекс (`POST /api/ugcpub/business-answer`) | отдельно, после проверки этапа 1 |

## Как работает

### Вход

Сессия — две cookies аккаунта Яндекса: `Session_id` и `sessionid2`. Берутся из переменных
окружения `YANDEX_BUSINESS_SESSION_ID` и `YANDEX_BUSINESS_SESSION_ID2` (локально — из `.env`,
он в `.gitignore`; на проде — `/opt/beer/.env`).

**Это сессия всего аккаунта Яндекса** (почта, Диск, платежи), а не ключ только к отзывам.
Поэтому:

- лучше завести отдельный аккаунт Яндекса, добавить его в Яндекс Бизнесе представителем
  организаций и брать cookies у него, а не у личного аккаунта владельца;
- cookies не присылать в чат и не класть в git — только в `.env`;
- клиент не печатает их, а из текста любой ошибки вырезает их значения (`_scrub`);
- сессия не вечная: выход из аккаунта («Выйти на всех устройствах») или смена пароля её
  убивает. Признак — переадресация на `passport.yandex.ru`, HTTP 401 или 488 →
  `YandexAuthError`: нужны новые cookies.

Как достать cookies: войти в этот аккаунт в браузере, открыть отзывы организации в Яндекс
Бизнесе, DevTools → Application → Cookies → `https://yandex.ru`, скопировать значения
`Session_id` и `sessionid2`.

CSRF-токен для чтения не нужен (пакет `ya-business-api` тоже не шлёт его на чтении). Он
понадобится на этапе 2 для ответа на отзыв: `POST /api/view/chain/0/list/` отвечает 488 с
полем `csrf`.

### Эндпоинты

`BASE_URL = https://yandex.ru/sprav`, все запросы без переадресаций (`allow_redirects=False`):

| Запрос | Ответ |
|---|---|
| `GET /api/companies?page=N` | `{limit, page, total, listCompanies: [...]}` — организации аккаунта, `type`: `ordinal` (точка) или `chain` (сеть) |
| `GET /api/chain/<tycoon_id>/branches/?chainPermalink=<permanent_id>&geoId=<geo_id>&page=N` | `{companyList: {pager, companies: [...]}, companyIds}` — филиалы сети |
| `GET /api/<permanent_id>/reviews?ranking_by=by_time&page=N` | `{page, currentState, list: {pager: {limit, offset, total, continue_token}, items: [...]}}` — отзывы, новые первыми |

Сети раскрываются в филиалы (`branches()`), повторы по `permanent_id` убираются. Связь с нашим
баром — по `permanent_id`, не по названию: название в кабинете могут поменять.

### Пагинация отзывов

По номеру страницы: `page=1, 2, ...`. `continue_token` в ответе есть, но сервер принимает его
только вместе с `unread=true` (так же строит запрос пакет `ya-business-api`). Если листать все
отзывы по `continue_token`, как в примере постановки, сервер будет возвращать первую страницу
снова и снова.

`unread` — отметка «прочитано» в кабинете: отзыв могли открыть в Яндексе раньше нас. Поэтому
«новый отзыв» у нас = `id`, которого ещё нет в хранилище.

Обход останавливается:

- на пустой странице;
- когда `offset + число отзывов на странице >= total`;
- на пределе страниц (`MAX_REVIEW_PAGES = 200`: это тысячи отзывов, больше, чем у любого бара);
- ошибкой `YandexFormatError`, если страница повторила уже полученные отзывы (сервер
  проигнорировал `page`) — вместо бесконечного цикла.

### Разбор отзыва (`parse_review`)

| Наше поле | Из Яндекса | Правило |
|---|---|---|
| `external_id` | `id` | ключ дедупликации вместе с `source = 'yandex'` |
| `rating` | `rating` | целое 1..5; иначе `None` и замечание в `problems` |
| `author` | `author.user` | `''` — нет имени; `author_privacy` — как пришло |
| `author_avatar` | `author.avatar` | ссылка или `None` |
| `text` | `full_text`, иначе `snippet` | `''` — только оценка |
| `created_at` | `time_created` | Unix-время → `YYYY-MM-DDTHH:MM` по Москве (формат хранилища отзывов); число больше 10^11 считается миллисекундами |
| `owner_reply` | `owner_comment.{text, time_created}` | ответ организации в Яндексе или `None` (пустой текст — не ответ) |
| `photos` | `photos[].{link, width, height}` | список |
| `lang`, `public_rating` | как есть | |

Неполная запись не бросает исключение: чего нет — `None` или `''` и строка в `problems`.
Служебные токены отзыва (csrf ответа, токены чата) не переносятся.

### Ошибки и повторы

| Ошибка | Когда | Повтор |
|---|---|---|
| `YandexAuthError` | нет cookies; переадресация на вход; 401; 488 | нет — сессия сама не оживёт |
| `YandexCaptchaError` | 429 с заголовком `need-captcha: 1` | нет — повтор только продлит капчу |
| `YandexTemporaryError` | сеть, таймаут, 500/502/503/504, 429 без капчи | 3 попытки, паузы 2 и 6 с (`RETRY_DELAYS_SEC`) |
| `YandexFormatError` | не JSON, не объект, нет ожидаемых полей, иной код, пагинация не работает | нет |

Между запросами подряд — пауза 0,5 с (`REQUEST_PAUSE_SEC`), чтобы не частить в чужой
внутренний API. Таймаут одного запроса — 20 с.

### Почему свой клиент, а не пакет `ya-business-api`

Постановка предлагает пакет `ya-business-api` 4.0.1 (MIT). Эндпоинты и приёмы взяты из него
(User-Agent браузера, cookie `i`, признаки протухшей сессии и капчи). Сам пакет не подключён:

- он требует `requests>=2.32.5` и `pydantic>=2.12.5`, а в образе закреплён
  `requests==2.31.0`, pydantic нет вовсе;
- в его модели отзыва около 14 обязательных полей, в том числе токены чата и csrf ответа.
  Если любое из них пропадёт у Яндекса, не разберётся вся страница отзывов. Здесь
  разбирается только нужное, остальное берётся по умолчанию;
- на ответ 5xx он падает на `assert` (`AssertionError`), а не понятной ошибкой;
- в примере постановки параметр `ranking=` — у пакета он называется `ranking_by`, а
  пагинация по `continue_token` без `unread` не работает (см. выше).

Весь код Яндекса — в одном файле. Если внутренний API изменится, правится только он.

### Отличия от постановки, принятые под наш проект

| Постановка | У нас | Почему |
|---|---|---|
| PostgreSQL, таблица `yandex_reviews` | `guest_reviews.json` (`core/guest_reviews.py`), поля `source = 'yandex'`, `origin = 'import'`, `external_id` уже есть | в проекте нет PostgreSQL; постановка разрешает расширить существующую модель |

### Сверка (`core/yandex_reviews_sync.sync_all`)

1. Cookies из окружения; нет — состояние `not_configured`, в Яндекс не ходит.
2. Граница истории `history_cutoff` = дата первой сверки − 30 дней (`HISTORY_WINDOW_DAYS`).
   Ставится один раз и дальше не меняется: иначе при сбое сверки дольше 30 дней свежие
   отзывы молча уходили бы в «историю».
3. Список организаций; для каждой из `BAR_BY_PERMANENT_ID` — все страницы отзывов,
   разбор, загрузка в хранилище (`upsert_imported`). Организации нет в аккаунте — ошибка
   этого бара, остальные сверяются.
4. Проход считается полным, только если получено ровно столько, сколько насчитывает Яндекс.
   Только тогда отзывы, которых в Яндексе больше нет, получают отметку `gone_at`
   («нет в Яндексе» на карточке). Из хранилища ничего не удаляется.
5. Итог — в `yandex_reviews_sync.json` (статус, время, ошибка, по барам — получено и
   счётчик Яндекса). Экран получает сводку в `yandex_sync` ответа `GET /api/reviews`.

| Статус | Когда | На экране |
|---|---|---|
| `ok` | все бары сверены | «Яндекс Бизнес: сверено <когда>. Сверка раз в сутки, утром.» |
| `partial` | часть баров с ошибкой | внимание, какие бары не сверены |
| `expired` | сессия не принята | опасность: «Вход в Яндекс Бизнес устарел… нужны новые cookies» |
| `captcha` | Яндекс просит капчу | внимание, следующая попытка завтра |
| `error` | не получен список организаций | опасность, текст ошибки |
| `not_configured` | cookies не заданы | «Яндекс Бизнес не подключён» |
| `running` | идёт сверка; дольше часа (`SYNC_STALE_MIN`) — считается прерванной | |

При `expired` сверка останавливается сразу (одна сессия на все бары), при временной
ошибке одного бара — продолжается с остальными.

### Статусы загруженных отзывов (`ReviewStore.upsert_imported`)

Ключ — пара (`source = 'yandex'`, `external_id` = id отзыва в Яндексе); повторная сверка
дублей не создаёт.

| Было у нас | В Яндексе | Стало |
|---|---|---|
| отзыва нет | есть ответ организации | «Отвечен», ответ из Яндекса: `reply = {text, at: время ответа в Яндексе, by: 'Яндекс Бизнес', delivered: true, source: 'yandex'}` |
| отзыва нет | ответа нет, дата раньше границы истории | «Без ответа по решению», причина «До подключения сервиса: в Яндексе без ответа» |
| отзыва нет | ответа нет, дата не раньше границы | «Без ответа» |
| «Без ответа» или «Без ответа по решению» | ответ появился | «Отвечен» с ответом из Яндекса |
| «Отвечен», ответ сохранён здесь | ответ появился | `delivered: true`, `published_at`, `source_text`; момент ответа (`reply.at`) прежний |
| «Отвечен», ответ из Яндекса | текст ответа изменили | новый текст, `edited_at`; `reply.at` прежний |
| «Отвечен», ответ из Яндекса | ответ удалили | «Без ответа», прежний ответ остаётся для истории (`removed_in_source_at`) |
| есть | отзыва нет (полный проход) | `gone_at`, запись остаётся |
| `gone_at` | отзыв снова есть | `gone_at` снимается |

Оценка, текст, автор и фото обновляются при каждой сверке. Отзыв без id, даты или оценки
1..5 не загружается и попадает в `stats.invalid` / `problems` (такой отзыв не считается
«пропавшим»).

На карточке ответ из Яндекса подписан «Ответ в Яндексе, <когда>»: у него только
«Скопировать» и «Сделать материалом» — править или возвращать его в работу здесь бессмысленно,
следующая сверка вернула бы его как было. Ответ, сохранённый здесь и найденный в Яндексе,
подписан «Опубликован в Яндексе».

**Пробный прогон на реальных данных** (дамп 2026-09-28, без обращений к Яндексу, граница
истории 29.08.2026): 358 отзывов, отвечены 252, без ответа по решению 106, ждут ответа 0.
Средняя оценка по нашим правилам — Крем 4,6, ВО 4,5, Вар 4,4, Лиговский 4,5. Рейтинг на

### Планировщик (`core/yandex_reviews_scheduler.py`)

- Ежедневно в `YANDEX_REVIEWS_SYNC_HOUR:YANDEX_REVIEWS_SYNC_MINUTE` **по Москве** (по
  умолчанию 08:30). Время считается через `core/msk_time`, а не наивное, как у других
  шедулеров, у которых наивное время на проде — это UTC.
- При старте приложения — разовая сверка, если успешной не было больше 20 ч
  (`STARTUP_STALE_HOURS`): первая загрузка идёт сразу после деплоя, новые cookies
  подхватываются перезапуском. Частые деплои не множат обращений к Яндексу.
- Без cookies или с `YANDEX_REVIEWS_SYNC_ENABLED=0` планировщик не запускается.
- Двойной запуск (два воркера gunicorn) исключён: lock-файл на дату + межпроцессный замок
  внутри `sync_all`.

### Включить на проде

1. Скопировать две строки `YANDEX_BUSINESS_SESSION_ID…` из локального `.env` в
   `/opt/beer/.env` на сервере.
2. Деплой (`git pull` + `docker compose up -d --build app`, [guides/deploy.md](guides/deploy.md)).
3. Через ~20 с после старта — первая сверка; на странице появится строка «сверено …».

Если на сервере вход не примут (Яндекс может не узнать сессию с чужого адреса), строка
станет красной «Вход в Яндекс Бизнес устарел»; тогда cookies берутся заново.
