# ClaudeHub: модели Research и Telegram

## Что это

Единый ключ `ClaudeHub` и четыре модели: `claude-opus-5-5`, `gpt-6.1-sol`,
`claude-fable-5-1`, `gpt-6-astra`. Fable 5.2 заменена на 5.1 по решению владельца.
В Research модель выбирается рядом с режимом ответа; в Telegram — `/model` и кнопками.
Выбор фиксируется в задании до очереди и используется также агентами. Настройка Telegram
хранится по ID пользователя в SQLite; браузер сохраняет выбор в localStorage отдельно
по ID вошедшего пользователя. Старые вопросы сохраняют прежнюю модель.

Подключение включается выбором ClaudeHub в админских настройках бота; ключ — в тех же
закрытых настройках либо переменной среды `ClaudeHub`. Секрет отдаётся только серверному
ключу `/api/bot/config`, не браузеру. У новых выбранных моделей effort=xhigh.

## Файлы

- `kultura_bot/engine/gateway.py` — разрешённый каталог, адреса, отдельный ключ,
  строгий разбор тарифов провайдера и ошибок внутри HTTP 200.
- `engine/gateway_client.py` — адаптер обычных функций к общему движку; тарифы каталога,
  учёт кэша, история, вложения, тайм-аут 600 с. Никаких прямых ключей на адрес шлюза.
- `engine/claude.py`, `engine/astra.py` — необязательный base_url при создании SDK;
  прежние адреса по умолчанию сохранены.
- `tests/test_kultura_gateway.py` — проверка адресов, секретов и тарифов.
- `engine/local_search.py` — локальный поиск по разрешённому каталогу, обычные функции
  без `defer_loading`, накопление найденных функций в пределах запроса.
- `scripts/claudehub_roundtrip.py` — отдельный живой read-only прогон через Chat
  Completions и существующий `tools.execute`/MCP; не рабочий цикл диалога.
- `tests/test_kultura_local_search.py` — полнота поиска, изоляция схем, цикл результата,
  отказ при выдуманном ответе без MCP и неизвестном инструменте.

## Как работает

Anthropic endpoint: `https://api.claudehub.fun`.
OpenAI Chat Completions base: `https://api.claudehub.fun/v1`.
Прямые ключи OpenAI и Anthropic не используются для стороннего адреса.
Тарифы берутся из каталога провайдера `/v1/models`, а не из прайса OpenAI/Anthropic.
Неизвестный тариф не считается нулевым; fast ×2 и наценка длинного контекста
не переносятся автоматически. Рабочее подключение меняется отдельно от установки кода; старые прямые подключения сохранены.

### Локальный поиск: согласованный обход, 17 ноября

Пользователь предложил выбор инструментов в коде сервиса и проверку полного цикла.
Реализован отдельный модуль: поиск слов/основ по именам, описаниям и параметрам
в уже разрешённом каталоге. Слова соединяются по ИЛИ; пустой запрос находит всё.
Нет прежней отсечки в шесть результатов. Это лексический поиск, не семантический:
подбор основ для произвольного вопроса и влияние на качество требуют отдельной оценки.
Обычная функция `kultura_find_tools` позволяет расширять выбор; найденные схемы
передаются как обычные функции без defer_loading. Это НЕ встроенный tool_search.
Широкая выдача разбита на страницы без потери доступа к каталогу; см. ниже рабочий цикл.

Живой прогон на сервере бота с gpt-6-astra / reasoning_effort=medium:
локальный поиск «справочник» выбрал 14 функций; модель вызвала common_bars_reference;
существующий tools.execute получил успешный ответ MCP; второй запрос модели получил
этот результат и вернул правильные четыре названия баров. Отправок в Telegram и
изменений данных не было. Это подтверждает конкретный полный цикл через Chat
Completions, а не hosted search, семантическую полноту поиска или качество исследований.
Исполнение прогона дополнительно ограничено одной read-only функцией.

Локальный поиск подключён к рабочему `agent.run_turn` через `ToolContext`.
Все реальные инструменты исполняет прежний `tools.execute`: права, остановка,
бюджеты, агенты, отчёты и маршрутизация карточек остаются общими. Поиск выдаёт
страницы по 100 совпадений, с next_offset; полный каталог доступен, нет отсечки шести.
В запросе не более 128 обычных функций; старые схемы можно загрузить снова по имени.
Бриф сохраняется, меняется только описание синтаксиса поиска.

Тарифы читаются из `/v1/models` (кэш 5 минут), неизвестный тариф — ошибка, а не ноль.
Режим fast для шлюза не заявлен и не тарифицирован провайдером: интерфейс его отключает,
а `/fast` идёт обычным запросом с уведомлением. Множитель ×2 прямого OpenAI не применяется.
Статистика времени разделена по провайдеру, модели и effort. 429 не вызывает автоматическую
повторную генерацию; общий интервал исходящих model-запросов — не менее 2,5 с.
Состояние рассуждений Claude сохраняется только для той же модели; при переходе на другую
модель остаётся каноническая история текста и вызовов. Отчёты обрабатывает штатный валидатор.

### Сравнение моделей: xhigh, два режима

`scripts/claudehub_compare.py` запускает по одному краткому ответу и полному отчёту
на каждой модели. Общий вопрос: «Какой день на лиговском меньше всего проходит в план?».
Для сопоставимости фиксированы октябрь 2026 и трактовка дня как дня недели:
суммарный факт / суммарный план, отдельно met/shifts. Одинаковые MCP-запросы получают
один снимок данных. Контрольный ответ MCP с финансовыми цифрами хранится только в закрытых артефактах
вне публичного репозитория.

Использован рабочий bot.md: заменён только раздел поиска, добавлены фиксированные
условия эксперимента. Агенты не подключены; запись/отправки запрещены, report/chart
перехватываются как тестовые артефакты. Это не проверка всей цепочки production UI.
Отчёты проходят normalize_report и отображаются тем же tg_chart.html / JS / CSS,
что на сайте. Артефакты с бизнес-данными хранятся вне публичного репозитория.

Усилие по умолчанию — xhigh: reasoning_effort для GPT, output_config.effort + adaptive
thinking для Claude. Принятие запроса шлюзом само по себе не доказывает внутренние
параметры модели за шлюзом. Нет автоматического понижения усилия.
Начальный лимит эксперимента 16K оказался недостаточным для полного Fable; повтор
использует рабочие settings.MAX_TOKENS (64K). После получения отчёта цикл заканчивается,
не делает лишний запрос за текстом: в первом Astra отчёт уже был получен, но последующий
запрос завершился upstream overloaded. Это не потеря созданного отчёта.

Краткие ответы всех моделей верны. Полные Opus, Sol и Astra прошли штатную валидацию.
Наблюдения: Opus подробно разобрал смены, но слишком уверенно приписал причину дню,
а не людям; Astra сделала таблицу из пяти колонок при рекомендации брифа до четырёх
и два раздела вместо 3–8. Это замечания качества, а не ошибки схемы.
Повтор полного Fable с 64K закончился тайм-аутом HTTP 240 с (268,7 с суммарно).
Готового полного отчёта Fable нет. Синхронный транспорт прогона отличается от рабочего
потокового; это ограничение теста, не доказательство слабости модели.
Замеры — отдельные прогоны, не статистический бенчмарк скорости или качества.

### Новый дословный прогон

По следующему запросу владельца скрипт больше не фиксирует период и трактовку,
не делает контрольный расчёт и не выбирает инструменты заранее. Текст user передаётся
дословно. Режим answer/report и текущая дата остаются служебным контекстом брифа.
API timeout — 600 секунд. У GPT нет max_completion_tokens в запросе. Anthropic
без max_tokens возвращает HTTP 400 / Field required; используется объявленный
шлюзом максимум 128000, а не прежние тестовые 16K/64K. Физические лимиты модели
сохраняются. После 429 тело повторяется без изменений, частота ограничена 24/min.
Результаты сохраняются без оценки правильности и редакторских исправлений.
В прогоне Fable шлюз вернул HTTP 402 insufficient_balance; повторять такие ошибки
автоматически или снижать запрошенный максимум не следует. Для длительных прогонов
результаты надо сохранять на сервере: обрыв SSH не должен терять ответы.
