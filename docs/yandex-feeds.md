# Фиды Яндекса (`/yandex`)

## Что это

Прайс-листы баров для карточек на Яндекс Картах (Яндекс Бизнес). На каждый бар
одна публичная ссылка в формате YML: меню кухни и разливное пиво 0,5 л. В карточке
можно указать только одну ссылку на прайс-лист, поэтому кухня и пиво в одном файле.

Страница `/yandex` (после входа) — редактор позиций: скрыть позицию, заменить
название, цену или описание, посмотреть черновик «как в карточке», увидеть сорта,
которые не попали в файл, и причину, переснять пиво по кнопке.

Решения владельца (2026-09-27):
- в Яндекс идёт **обычный прайс** iiko для всех баров; ценовые категории
  («Андреевский Двор», «Лиговский проспект») не применяются, хотя на ВО и Лиговском
  по ним пробивают. Это не ошибка, не «чинить»;
- если на кегу заведено несколько блюд 0,5 л с разной ценой — берётся цена самого
  свежего приказа и страница показывает предупреждение;
- пиво в прайс-листе карточки Яндекс принимает, если файл не используется для
  рекламы. Подключать только через «О компании → Товары и услуги», не через
  «Продвижение → Материалы».

## Как работает (с примерами и формулами)

### Ссылки

| Ссылка | Что внутри | Кто использует |
|---|---|---|
| `/feeds/kitchen/bar1` … `bar4` | кухня + пиво 0,5 л бара, правки применены | карточка бара в Яндекс Бизнесе |
| `/feeds/taplist.yml?bar=barN` | то же, что `/feeds/kitchen/barN` | старая ссылка |
| `/feeds/taplist.yml` | пиво всех баров из снимка, разделы = бары | служебная, в iiko не ходит |
| `/feeds/kitchen.yml` | исходный файл меню кухни, общие правки кухни применены | старая ссылка, в карточку не вставлять |

Бары: `bar1` Большой пр. В.О, `bar2` Лиговский, `bar3` Кременчугская, `bar4` Варшавская.
Публичные ссылки отдают `Cache-Control: public, max-age=300`, API страницы — `no-store`.

### Пиво 0,5 л: какая цена идёт в файл

Порции и цены кеги в баре собирает `enrich_prices` (правила — [taplist-v2.md](taplist-v2.md),
«Точная цена и порция»). Из них `choose_serving` выбирает одну:

1. Порции ровно 0,5 л с ценой > 0.
2. Навынос отбрасывается: «(б)», «с собой», «навынос» в названии блюда или размера.
   В карточке заведения — цена в зале.
3. Одна цена у всех оставшихся блюд — она идёт в файл.
4. Цены разные — берётся цена приказа с самой поздней датой начала (`dateFrom`),
   на странице предупреждение со списком блюд, цен и дат.
5. Если у самых свежих приказов цены всё равно разные или дат нет
   (цена по умолчанию `defaultSalePrice`) — сорт в файл **не идёт**, причина видна
   в блоке «Не попали в файл». Угадывать цену нельзя.

Пример (Kwak, 27.09.2026): «ВО Квак (0,5)» 1580 ₽ (приказ от 01.02.2024) и
«Квак (0,5)» 1350 ₽ (приказ от 01.09.2026) → в файле 1350 ₽. Пример навынос:
«ВО Коникс Черри Руби (0,5) (б)» 280 ₽ отбрасывается → 590 ₽.

Цена в файле — Decimal, два знака (`1350.00`), без пересчёта.

### Какие сорта не попадают в файл

| Причина | Что делать |
|---|---|
| Нет проверенной карточки сорта (Untappd) | уточнить сорт на странице кранов |
| Причина из iiko (`price_message`): расписание, свободная цена, нет цены | исправить в iiko |
| В iiko нет порции 0,5 л (перечислены имеющиеся) | завести блюдо 0,5 л |
| Порция 0,5 л только навынос | завести блюдо в зале |
| Разные цены 0,5 л, свежий приказ не определить | оставить одно блюдо 0,5 л на кегу |

После исправления — «Переснять пиво».

### id позиции

Пиво: `bar1-u<id сорта Untappd>-p05`, например `bar1-u6240484-p05`. Позиция привязана
к сорту, а не к крану: смена кеги не переносит правки на другой сорт, переезд на
другой кран их не теряет. Один сорт на двух кранах — одна позиция («Краны 3, 5»).
Кухня: id из меню (`ttk-s02`), одинаковый во всех барах.

До 2026-09-27 id пива был `barN-tapM-p05` (по крану) — отсюда перенос правок ниже.

### Название и описание пива

- Название: `«<пивоварня> <сорт>, 0,5 л»`. Пивоварня не добавляется, если уже есть в
  названии сорта целиком или её значимое слово стоит первым в названии
  (`Pivovar Zubr` + `Zubr Gold` → «Zubr Gold, 0,5 л»). Служебные слова пивоварни
  (Brouwerij, Pivovar, Brewery, Пивоварня и т. п.) не считаются. `vendor` — пивоварня целиком.
- Описание: текст Untappd (до «NB:» — дальше служебные пометки), затем «Стиль»,
  «Крепость», «Горечь» и «Порция: 0,5 л.». Если текста Untappd нет, описание уже
  собрано из стиля/крепости/горечи — второй раз не добавляются. Каждая часть — одно
  предложение с одной точкой; серия из двух и больше точек становится «…».
  Номер крана в описание не пишется. Предел 3000 символов, в карточке видно ~250.

### Кухня

Из `resources/kitchen_menu.yml` (в образе) при каждом запросе: деплой обновляет кухню
сразу. Цены кухни с iiko не сверяются — меняются в этом файле или правкой на странице.
Фото — с нашего сайта (`/static/kitchen-menu/`), у 27 из 29 блюд.

### Правки

Файл `yml_overrides.json`, схема 2:

```json
{"schema": 2, "feeds": {
  "kitchen": {"ttk-s02": {"hidden": true}},
  "bar1": {"bar1-u6240484-p05": {"hidden": false, "price": "999.00"}}
}}
```

- Кухня — ключ `kitchen`, общий на все бары. Сохранение правки блюда снимает правки
  этого блюда у отдельных баров.
- Пиво — ключ бара.
- Приоритет в файле бара: `kitchen` < старые `kitchen-barN`, `taplist-barN` < `barN`.
  Правка позиции заменяется целиком.
- Пустое поле = «как в источнике». Правка без полей и без скрытия удаляется.
- Название ≤ 200, описание ≤ 3000 символов; управляющие символы убираются
  (иначе XML всего бара невалиден), пробелы и переводы строк схлопываются в один пробел.
- Цена: пробелы (включая неразрывный) убираются, запятая = точка, округление до копеек
  **ROUND_HALF_UP** (`0,125` → `0.13`), затем проверка `0 < цена ≤ 100 000` уже по
  округлённому (`0.001` → ошибка). Ошибка называет позицию: «Kwak»: цена должна быть…
- Одновременная работа: страница отправляет только изменённые позиции и с каждой —
  `base`, правку, которую видела при загрузке. Если сейчас действует другая правка,
  сервер ничего не пишет и отвечает 409 со списком позиций; страница обновляет только их.
- Запись атомарная (tmp + fsync + replace), прошлая исправная версия — в `.bak`.
  Битый файл читается из `.bak`; если битые оба — фиды отвечают 503 (публиковать без
  правок нельзя: скрытые позиции снова попали бы на Карты).

Перенос схемы 1 (разово, при первом обращении после деплоя 2026-09-27; исходник в
`yml_overrides.json.v1.bak`):
- правка `barN-tapM-p05` переходит на сорт, который стоит на кране M **сейчас**, с
  пометкой `migrated_from_tap`; страница просит проверить («Всё верно» / «Удалить правку»);
  пустой кран — правка удаляется (в лог);
- одинаковая правка блюда во всех четырёх барах становится общей, разные остаются у баров.

Правки сортов, которых сейчас нет на кранах, не удаляются: они сработают, когда сорт
вернётся. Страница показывает их списком «Правки без позиции в файле» с кнопкой удаления.

### Снимок пива

`yml_bar_snapshot.json`, схема 2: по бару список пива, «не попали в файл», ошибка,
время списка пива, число активных кранов. Кухни в снимке нет.

- В 05:00 МСК поток планировщика (один на все воркеры gunicorn, лок
  `data/.yml_refresh.lock`) снимает пиво по всем барам; прайс iiko — один запрос на все бары.
- Кнопка «Переснять пиво» — `POST /api/yml/refresh`; и она, и планировщик берут лок
  прогона `data/.yml_refresh_run.lock`: второй запуск во время первого — 409.
- Снимок старой схемы (до деплоя 2026-09-27) переснимается сразу, до первого снимка
  пиво собирается прямо на запрос.
- Бар не собрался или **0 сортов при активных кранах** — это ошибка, а не «успех»:
  остаётся прошлый список пива, если ему не больше 48 часов (дальше пиво бара не
  показывается), ошибка видна на странице и у бара красная точка.
- Ошибки по барам — до 6 попыток в день каждые 10 минут. Прайс iiko недоступен —
  повтор каждые 10 минут без предела, файлы отдают прошлый снимок.
- Тревога в Telegram (чаты тревог open-check: `TELEGRAM_ALARM_CHAT_IDS` + подписчики)
  — не чаще раза в день. Страница помечает снимок старше 26 часов.

### Страница `/yandex`

Сверху — бары (точка: зелёная — всё в файле, жёлтая — есть не попавшие сорта,
красная — ошибка снимка), ссылка бара и «Как подключить». Ниже — время снимка,
счётчики и предупреждения. Список позиций по разделам: переключатель «в файле», фото,
название, краны, цена (исходная зачёркнута, если своя). Клик раскрывает редактор:
у каждого поля исходное значение и «Вернуть исходное», у цены — откуда она (приказ и
дата, блюдо), у описания — счётчик и граница видимого в карточке. Поиск и фильтры
«С правками», «Скрытые», «Проверить». Справа (на телефоне — вкладкой) черновик
«Как в карточке». Несохранённое держится в панели внизу (Ctrl+S), при переходе к
другому бару и закрытии вкладки — предупреждение. Утром открытая вкладка
перечитывает бар сама, если в ней нет несохранённых правок.

### XML

`yml_catalog@date` (время отдачи, МСК) → `shop`: название «Пивная культура, <бар>»,
компания, `url` сайта, валюта **RUB** (справка Яндекс Бизнеса: RUB, KZT, BYN; до
2026-09-27 было RUR), разделы, `delivery=false`, `pickup=true`, позиции:
`price`, `currencyId`, `categoryId`, `picture` (только https), `name`, `vendor`,
`description`, `param Объём`. `<url>` у позиций не пишется: корень сайта — дашборд
за логином.

### Проверка на живых данных 2026-09-27

Новое правило цены на живом прайсе iiko против опубликованных фидов: из 59 сортов на
кранах цена меняется у 19, ни один не выпадает: Kwak 1580 → 1350, Konix Cherry Ruby
280 → 590 (была цена навынос), Riegele Urhell 270 → 770 (была цена чужого блюда
«Брю Дог Зомби Кейк»), Festhaus Helles/Weissbier 420 → 470, Brewlok IPA 420 → 490,
Brewlok Stout 420 → 440. По всем 1692 парам «кега × бар» из реестра: 1464 без
изменений, 144 меняют цену, 84 уходят в «не попали»: 80 — у кеги в этом баре порция
0,5 л есть только навынос (цена навынос отличается от зала, у Konix 280 против 590),
4 — разные цены без различимой даты приказа.
