# GPT-6 Astra для kultura.research и @MCPkulturabot

## Что это

Второй провайдер общего движка Research и Telegram: OpenAI Responses API,
`gpt-6-astra`. Новая версия кода **не переключает провайдера сама**. Выбор модели
и ключ — `/admin/mcp`, раздел бота. Anthropic остаётся совместимым вариантом,
но для отката на него нужен действующий ключ: в момент разработки такого ключа нет.

## Файлы

| Файл | Назначение |
|---|---|
| `kultura_bot/engine/astra.py` | Responses, поток, перевод истории и вложений, тарифы, ошибки |
| `kultura_bot/engine/providers.py` | Неизменяемый выбор провайдера/модели на один вопрос |
| `kultura_bot/engine/agent.py`, `service.py` | Общие инструменты, агенты, бюджеты, оба канала |
| `kultura_bot/credentials.py`, `routes/mcp.py` | Настройки/ключи, серверный API и админская форма |
| `scripts/kultura_astra_eval.py` | Сохранённые ответы как материал для сравнения, без Claude API |
| `tests/test_kultura_astra.py`, `test_kultura_bot_site.py` | Контракт API и регрессии |

## Как работает

Актуально с 2026-11-17: штатный серверный поиск OpenAI по всему разрешённому
каталогу роли. Уровень по умолчанию — `medium` у бота и агентов. Явно сохранённое
усилие имеет приоритет; при рабочем переключении выбрать medium в настройках.

`Research / Telegram → Service.answer → выбранный API → tools.execute → MCP сайта`.
OpenAI не подключается напрямую к удалённому MCP. Функции выполняются прежним
исполнителем: права, скрытые инструменты, агенты по разделам, подстановка chat_id,
карточки Research, ограничения отчёта и защита от повтора неизвестной отправки
остаются общими. Anthropic-определения каталога используются как существующий
внутренний контракт и переводятся в Responses на границе адаптера. Так добавление
провайдера не меняет fingerprint и не обнуляет диалоги.

Запрос Responses: `store=false`, reasoning `medium` по умолчанию, серверный `tool_search`, отложенные функции с `defer_loading`, `strict=false` (исходные MCP-схемы содержат
необязательные поля; сайт проверяет их при исполнении). `max_output_tokens=64000`
включает рассуждения. PDF и изображения — `input_file` / `input_image`, таблицы
остаются текстом. Отказ или усечённый вызов не выполняется; невалидный JSON возвращает
ошибку инструмента. `/fast` использует `service_tier=fast`; при отказе мощности —
обычный режим и существующая пауза fast. Цена учитывает фактический tier ответа.

Каталог функций и `tool_search` с `execution=server` передаются API. Базовые функции
видны сразу, остальные сохраняют `defer_loading=true`. OpenAI ищет по всему
разрешённому каталогу и загружает найденные схемы. Нашего ранжирования, пагинации
и ограничения шестью результатами нет. Конкретную выдачу определяет OpenAI.
Результаты поиска сохраняются в provider_state и передаются при продолжении;
выполнение функций остаётся у прежнего tools.execute с прежними правами.

Схема соответствует прежнему циклу Anthropic: поиск → функции → данные → анализ.
Алгоритмы поиска двух провайдеров не обещаются идентичными. По документации OpenAI
у отдельных deferred functions модель сначала видит имя и описание; откладывается
схема параметров. Поэтому прежний замер 10553 токена для локального поиска к этой
версии не относится. Группировка в namespaces не добавлялась, имена функций сохранены.

Живой тест малого каталога из 12 функций: Astra medium вернула tool_search_call,
tool_search_output и вызов запрошенной metric_07. 709 входных и 87 выходных токенов.
Рабочие MCP и отправка сообщений в этом тесте не вызывались. Это проверка протокола,
не приёмка качества полного бизнес-отчёта.

История не переписывается при смене модели. Старые тексты, вызовы и результаты
переводятся в Responses без подписей thinking Anthropic. Новые сообщения содержат
блок `provider_state` версии 1 с оригинальными output items OpenAI и обычные блоки
текста/вызовов для общего движка. Opaque reasoning и tool search возвращаются в
прежнем порядке, не удваиваются. Anthropic получает только обычные блоки.
Server-side compaction включается на 200K токенов: следующий запрос начинает с
последнего compaction item. Прежний сброс длинной истории по 300K символов для OpenAI
не применяется; таймаут простоя и изменение fingerprint по-прежнему следуют правилам
сервиса. Отчёты и история вопросов сайта хранятся независимо от истории модели.
`store=false` не означает Zero Data Retention: правила хранения API проверяются
отдельно в проекте OpenAI.

Ключ, модель и усилие фиксируются для начатого вопроса, включая агентов и завершение
отчёта. Обновлённые настройки применяются к следующему вопросу. Журнал записывает
фактический выбранный provider/model. Старое поле статуса `claude_error` сохранено
для совместимости, теперь в нём также ошибки OpenAI.

### Настройки и совместимость

- `kultura_bot_provider`: `anthropic` (умолчание) / `openai`.
- `kultura_bot_openai_key`: ключ проекта OpenAI. Запасной источник —
  `KULTURA_BOT_OPENAI_KEY`. Как и прежний ключ, возвращается **только** серверу бота
  с его ключом; администратору — признак наличия и маска.
- `kultura_bot_effort`: `low`, `medium`, `high`, `xhigh`, `max`; для основной модели и агентов.
- `GET /api/bot/config` сохраняет прежние поля и добавляет `provider`, `model`,
  `effort`, `agent_effort`, `openai_key`. Новый движок понимает старый ответ как Anthropic.
- Отсутствие ключа Anthropic не мешает OpenAI. Research и watchdog используют
  ключ выбранного провайдера. Проверка ключа OpenAI — бесплатный запрос конкретной
  модели; успешная проверка не доказывает качество или доступный баланс генерации.

### Стоимость

По прайсу Astra, проверенному 2026-11-16, за миллион токенов: вход $10, выход $50,
чтение кэша $1, запись $12.50. `input_tokens` Responses включает cache read/write:
адаптер вычитает их из обычного входа, чтобы не считать дважды.

`стоимость = (обычный_вход × 10 + cache_read × 1 + cache_write × 12.5 + выход × 50) / 1e6`.

Если весь вход >272000 токенов, входные/кэшевые тарифы ×2, выходной ×1.5 для всего
запроса. Fast ×2 поверх этого. Reasoning уже входит в output, второй раз не добавляется.
Лимиты $2/$5/$15 не увеличены. Это мягкие пределы: проверка идёт между запросами,
последний запрос может превысить остаток бюджета. При равных обычных токенах Astra
в 2.5 раза дороже тарифа Opus 5.5, заложенного в проекте.

### Проверка на сохранённых ответах

Claude API для сравнения не нужен. Экспорт сохранённых ответов хранится **вне Git**,
с правами 0600; вопросы/ответы и бизнес-данные нельзя добавлять в публичный репозиторий.
Подготовка без сети:

```bash
python scripts/kultura_astra_eval.py --baseline /private/saved-answers.json --out /private/cases.json
```

Формат baseline: `records` из журнала (`uid`, `question`, `answer`, `asked_at`,
`model`, `cards`, `calls`), необязательные `web` и `reports` (id → тело отчёта).
Короткие продолжения без контекста и служебные команды не считаются самостоятельными
вопросами. Модель не видит эталонного ответа при генерации.

Платный прогон выбранного вопроса (ключи уже в окружении):

```bash
python scripts/kultura_astra_eval.py --baseline /private/saved-answers.json \
  --out /private/result.json --run --ids ID_ВОПРОСА --max-cost-usd 0.5
```

Прогон берёт только MCP-функции с `readOnlyHint=true`, исключает скрытые инструменты.
Отчёты и графики проверяет настоящими валидаторами, сохраняет локально, не отправляет.
Нет доступа к изменению данных, очереди Research или Telegram. Дата исходного вопроса
явно передаётся модели. Исторические снимки исходных данных не всегда доступны:
нынешние остатки нельзя сравнивать со старыми как с одинаковыми данными.
Результат всегда `requires_review`: сверить цифры, даты, источники, полноту и структуру.
Сохранённый ответ не считается безошибочным эталоном автоматически.
4096 output tokens по умолчанию — короткая проверка подключения, не приёмка качества
сложного исследования; для такой проверки выставить 64000 с подходящим бюджетом.
Если дневной предел прервал проверку, файл результата сохраняет `status=budget`,
фактические cost/steps, usage каждого шага и уже созданные локальные карточки.
Общий движок завершает вопрос успешно, если карточка уже доставлена и бюджет
вопроса/суток исчерпан: дополнительная платная реплика не требуется. Ошибка доставки
не считается успехом. Это действует для обоих провайдеров и обоих каналов;
парные результаты вызовов сохраняются в истории.

### Выкладка

До переключения: весь CI, проверка ключа и реальных ответов Astra, ручная оценка
сохранённых примеров, тест обоих каналов. В этой реализации настройки позволяют
переключить новые задания общей настройкой; маршрутизация по отдельным пользователям
и автоматический drain развёртывания не добавлены.

Публикация секрета облачной среды даёт ключ локальным проверкам Codex, но сама по себе
не настраивает сервер сайта. При выкладке ключ нужно безопасно задать в настройках
сайта или его `KULTURA_BOT_OPENAI_KEY`; сервер бота получит его через защищённый
`/api/bot/config`. До этого производственный провайдер не переключать.

Бот забирает main каждые две минуты независимо от CI сайта. Не сливать в main до
готовности и не включать OpenAI, пока новые версии не стоят на **обоих** серверах.
Перед релизом проверить пустую очередь и отсутствие активных вопросов, сохранить
резервную копию БД и выполнить контролируемый перезапуск. Текущий graceful shutdown
90 секунд не гарантирует завершения длинного исследования. Работающий второй
Telegram polling-процесс с тем же токеном не запускать.

Возврат настройки Anthropic возможен только с рабочим ключом. Если его нет, аварийный
вариант — пауза приёма новых заданий и исправление OpenAI/возврат совместимой версии
кода; нельзя обещать автоматическое восстановление ответов через Claude.
