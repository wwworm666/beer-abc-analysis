## Что это

Страница `/stocks` («Заказы и остатки») — шесть вкладок: Сводный заказ (по умолчанию),
Таплист, Фасовка, Сроки годности, Меню кухни, Формирование заказа. Backend —
Blueprint `stocks_bp` в `routes/stocks.py`, шаблон `templates/stocks.html`.
Основной документ модуля — [docs/stocks.md](../../stocks.md), но его разделы Taplist /
Kitchen / Bottles описывают не ту реализацию, что в коде (см. раздел 6).

## Файлы

- `routes/stocks.py` — все эндпоинты (`/api/stocks/*`, `/api/chz/*`).
- `templates/stocks.html` — UI всех вкладок, корзина, CSV-экспорт.
- `core/olap_reports.py` — `get_store_balances`, `get_store_operations_report`, `get_nomenclature`.
- `extensions.py` — `get_cached_nomenclature`, `BARS`, `taps_manager`.
- `core/taps_manager.py`, `core/iiko_barcodes.py`, `chz_test/chz.py`, `remote_exec.py`, `core/chz_scheduler.py`.
- Документация: `docs/stocks.md`, `docs/chz-stock-integration.md`, `docs/expiration.md`, `wiki/content.md` (раздел «Заказы и остатки»).

## 1. Как проводился аудит

- Шесть независимых прочтений подсистем (order-board, taplist/kitchen/bottles,
  ЧЗ + expiry, шаблон, зависимости core, документация и история).
- Пять «искателей» с разными линзами (docs↔код, расчёты, контракт фронт↔бэк,
  эндпоинты, надёжность): 91 находка, после дедупликации 67.
- Адверсариальная проверка прошла только для двух находок (S-01, D-02): обе
  подтверждены тремя рецензентами. Остальное перепроверено выборочно по коду
  вручную; колонка «Проверка» в реестре: «код» — подтверждено по исходникам,
  «N аг.» — найдено N независимыми агентами.
- Хелперы `_velocity`, `_calc_recommendation`, `_urgency_level` прогнаны на
  граничных значениях (таблица в разделе 4).

## 2. Как страница устроена на самом деле (кратко)

Выбор бара или кнопка «Обновить данные» запускает пять параллельных запросов сразу
для всех вкладок (`templates/stocks.html:911-928`). Переключение вкладок ничего не
грузит. Каждый эндпоинт сам авторизуется в iiko, тянет `balance/stores` и (кроме
таплиста) полный XML `storeOperations` за 30 дней. Кэша нет.

| Вкладка | Эндпоинт | Источники | Ключевая логика |
|---|---|---|---|
| Сводный заказ | `GET /api/stocks/order-board?bar=` (`routes/stocks.py:1165`) | номенклатура, balances, storeOperations, баркоды XML, кэш ЧЗ | classify → stock, avg_sales, velocity, recommended, urgency; сортировка по срочности, затем days_left |
| Таплист | `GET /api/stocks/taplist` (`:156`) | `taps_manager.get_bar_taps`, balances | только GOODS в литрах, точное совпадение нормализованного имени с активным краном; уровень по литрам: <0 negative, <10 low, <25 medium, иначе high |
| Фасовка | `GET /api/stocks/bottles` (`:560`) | номенклатура (группа «Напитки Фасовка»), balances, storeOperations | stock, avg_sales за 30 дней, уровень по days_left: <3 low, <7 medium, иначе high |
| Сроки годности | `GET /api/stocks/expiry` (`:923`), `POST /api/chz/refresh` (`:872`), `GET /api/chz/refresh/status` (`:883`) | то же + `chz_test/debug/chz_stock.json` через баркод → GTIN → КПП бара | nearest_expiry, партии; view-only; кнопка запускает SSH-цепочку на бар-ПК |
| Меню кухни | `GET /api/stocks/kitchen` (`:388`) | balances, storeOperations | белый список 13 поставщиков подстрокой в `category`, минус пивные ключевые слова |
| Формирование заказа | нет запросов | память браузера `ordersByBar` | один CSV на поставщика через все бары; корзина теряется при перезагрузке |

Дополнительно: `GET /api/stocks/chz` (`:731`) — legacy, синхронный вызов ЧЗ, UI не
использует; `GET /api/chz/stock` (`:780`) — сырой кэш ЧЗ, UI не использует.

Формулы «Сводного заказа» (`routes/stocks.py:76-152`, `:1304-1346`):

```
avg_sales    = Σ|amount| записей storeOperations с incoming != 'true' за 30 дней / 30
weekly_sales = avg_sales × 7
velocity     = dead (avg <= 0) | slow (weekly < 1) | regular (weekly < 7) | fast
days_left    = stock / avg_sales                      (None при avg_sales = 0)
target_stock = avg_sales × (lead_time_days + SAFETY_DAYS=3)
recommended  = ceil((target_stock − stock) / pack_size) × pack_size
               = 0 при dead/slow, при 0 <= days_to_expiry < 14, при дефиците <= 0
urgency      = critical (stock < 0) → low (dead/slow) → critical (days_left < 1)
               → high (days_left < lead) → medium (< lead + 3) → low
```

Поставщик = `category` номенклатуры. `SUPPLIER_PARAMS` содержит только 13 кухонных
поставщиков; все пивные получают `lead_time_days=3`, `pack_size=1`.

## 3. Решения владельца (2026-09-10)

| Вопрос | Решение |
|---|---|
| Что считать расходом | Расход считается вместе с перемещениями между барами (текущее поведение по типам документов сохраняется; исправлять нужно только скоупинг по бару, см. S-01) |
| pack_size для кег | Для кег pack_size не нужен |
| Что такое «кухня» на этой странице | Кухня = группа «ЕДА» (как на дашборде с 2026-07-16, `core/dashboard_analysis.py:15`), а не белый список поставщиков |
| Порядок работ | Сначала разобраться, как сделать страницу удобной и интуитивной для заказа, чтобы ей начали пользоваться; к реестру проблем вернуться после |

## 4. Граничные прогоны хелперов

| Вход | Результат |
|---|---|
| avg_sales = 1/7 (ровно 1 в неделю) | regular, не slow |
| days_left == lead_time | medium; days_left == lead_time + 3 → low |
| days_to_expiry = 13 | recommended 0; = 14 → обычный расчёт |
| days_to_expiry = -1 (просрочено) | не блокирует, recommended считается как обычно |
| stock = 0, velocity slow | urgency low, recommended 0 |
| stock = -0.04 | critical, в ответе показано как -0.0 |
| stock = 2.4, avg = 0.4 | days_left 5.9999… → medium, в таблице 6.0 |
| pack_size = 6, дефицит 7.2 | recommended 12 |
