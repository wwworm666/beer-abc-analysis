# Бот @MCPkulturabot (`kultura_bot/`)

## Что это

ИИ-помощник владельца сети «Культура» в Telegram. Отвечает по данным сайта: у него те же
инструменты, что у ИИ-агентов по MCP ([mcp.md](mcp.md)), и каждый вызывает настоящий расчёт
страницы от имени администратора. Думает через Claude API по отдельному ключу Anthropic.
Большие задачи по одному разделу поручает агентам: «Аналитик», «Зарплаты и график», «Контент».
Графики присылает картинкой с кнопкой «Открыть интерактивно» ([tg-miniapp.md](tg-miniapp.md)).

**Работает на отдельном сервере в Амстердаме**, а не на сервере сайта: сайт стоит в России, где
API Anthropic недоступен. Сайт к Anthropic не обращается вовсе — разговор с Claude ведёт сервер
бота, а данные берёт у сайта по MCP, как остальные агенты:

```
Telegram  <->  сервер бота (Амстердам)  <->  Claude API (Anthropic)
                       |
                       +-- HTTPS -->  beerkultura.ru
                                        MCP /mcp, /mcp/<раздел>   правила, инструменты, вызовы, графики
                                        API бота /api/bot/*       настройки, привязки Telegram, отчёт
```

Решения владельца 2026-10-19: бот — отдельная папка внутри репозитория, все настройки и
инструкции бота и его агентов лежат в проекте, отдельный ключ Anthropic для бота — нормально;
бот работает на сервере в Амстердаме («как раз чтобы бот там и работал»), а владелец не
вписывает руками ни id пользователей, ни настройки на сервере: установка — одна команда со
страницы, дальше сервер обновляется из GitHub сам.

**Где что менять:**

| Что | Где | Когда подействует |
|---|---|---|
| Как бот отвечает: тон, формат, правила | `kultura_bot/prompts/bot.md` | через 2–3 минуты после слияния в `main` (самообновление, раздел 3); идущие диалоги начнутся заново с пометкой «Обновились инструкции бота» |
| Общие правила всех агентов, формат отчёта боту | `kultura_bot/prompts/agent.md` | так же |
| Агент: разделы, когда поручать, правила | `kultura_bot/agents/<имя>.md` (новый файл — новый агент) | так же |
| Модель, усилие, быстрый режим, пределы шагов, дневной предел расхода, диалог | `kultura_bot/settings.py` | так же |
| Правила и описания инструментов сайта (общие для бота и MCP-агентов) | `INSTRUCTIONS` и `ToolSpec` в `core/mcp/tools/<раздел>.py` | после выкладки сайта; бот подхватит не позже чем через 10 минут (`CATALOG_TTL_S`) |
| Графики: кнопка, short name мини-приложения, суточный предел | `kultura_bot/settings.py` (`CHART_*`, `MINIAPP_*`) | после выкладки сайта: графики рисует и шлёт сайт |
| Токен бота, ключ Anthropic, пауза | страница `/admin/mcp`, раздел «Бот @MCPkulturabot» | за 30 секунд, без выкладки |
| Кто может писать боту | там же: «Подключить мой Telegram», «Отключить» | сразу |
| Установка и переустановка сервера бота | там же: «Команда установки» | после выполнения команды на сервере |

Секретов в репозитории нет: он публичный, токен и ключ оттуда забрал бы кто угодно. На
сервере бота лежит только ключ сервера (раздел 4), токен Telegram и ключ Anthropic сервер
каждый раз берёт у сайта.

## Как работает

### 1. Почему Амстердам

Сайт (beerkultura.ru) стоит на сервере в России, а API Anthropic из России недоступен:
запросы получают отказ (403) или не доходят. Обходить это прокси с сервера сайта нельзя —
это обход региональных ограничений Anthropic. Поэтому всё, что говорит с Claude, работает на
сервере в Амстердаме, а сайт отвечает этому серверу. С Telegram сервер бота тоже говорит
напрямую: блокировок входящих соединений, как у сервера сайта, там нет.

### 2. Установка (один раз)

1. На странице `/admin/mcp`, раздел «Бот @MCPkulturabot», кнопка «Команда установки».
   Сайт выпускает новый ключ сервера бота (раздел 4) и показывает один раз команду:

   ```
   curl -fsSL https://raw.githubusercontent.com/wwworm666/beer-abc-analysis/main/kultura_bot/deploy/install.sh | KULTURA_BOT_KEY='kmcp_…' bash
   ```

2. Её выполняют на сервере в Амстердаме под root (`ssh root@<сервер>`, вставить, Enter).
   Скрипт ([install.sh](../kultura_bot/deploy/install.sh)):
   1. проверяет: root, ключ вида `kmcp_…`, есть systemd;
   2. ставит `git` и `curl`, если их нет (apt / dnf / yum);
   3. ставит `uv` в `/usr/local/bin` и им — Python 3.10+ для бота в `/opt/kultura-bot/python`
      (системный Python не трогается);
   4. заводит системного пользователя `kultura-bot` без входа: бот работает от него, не от root;
   5. забирает из GitHub папку `kultura_bot/` ветки `main` в `/opt/kultura-bot/repo`
      (частичный клон без истории: других папок репозитория там нет; файлы корня git кладёт
      всегда, бот их не использует);
   6. ставит зависимости в `/opt/kultura-bot/venv` (`deploy/requirements.txt`);
   7. пишет `/etc/kultura-bot.env` — ключ сервера и адрес сайта, права 600 (читает только root,
      systemd передаёт службе);
   8. ставит службы `kultura-bot` (бот) и `kultura-bot-update.timer` (самообновление),
      включает их и запускает бота; запоминает выложенную версию в `/opt/kultura-bot/deployed`;
   9. через 8 секунд показывает, запустился ли бот, и последние 15 строк журнала.
3. Через минуту строка состояния на странице — «Бот @MCPkulturabot работает…».

Повторный запуск команды безопасен: обновит код, ключ и службы и перезапустит бота. Новая
команда — новый ключ: прежний сразу отзывается, а сервер со старым ключом замолкает.

Что где на сервере:

| Путь | Что |
|---|---|
| `/opt/kultura-bot/repo` | папка `kultura_bot/` из GitHub |
| `/opt/kultura-bot/venv`, `/opt/kultura-bot/python` | Python и зависимости бота |
| `/opt/kultura-bot/deployed` | выложенная версия (коммит `main`) |
| `/etc/kultura-bot.env` | `KULTURA_BOT_KEY`, `KULTURA_SITE_URL` (права 600) |
| `/var/lib/kultura-bot/bot.db` | своя база: диалоги, вопросы, расход (раздел 10) |
| `/etc/systemd/system/kultura-bot*.service`, `.timer` | службы |
| `/usr/local/sbin/kultura-bot-update` | скрипт самообновления |

Служба `kultura-bot`: `python -m kultura_bot` от пользователя `kultura-bot`, перезапуск при
падении через 10 с, остановка — до 90 с на начатые ответы (`TimeoutStopSec=90`); файловая
система только для чтения, кроме своей папки данных (`ProtectSystem=strict`, `StateDirectory`).

Команды на сервере:

```
systemctl status kultura-bot            # работает ли
journalctl -u kultura-bot -f            # журнал бота
journalctl -u kultura-bot-update -n 50  # журнал обновлений
systemctl restart kultura-bot           # перезапуск
```

### 3. Самообновление

`kultura-bot-update.timer` раз в 2 минуты (`OnUnitActiveSec=2min`, разброс до 20 с) запускает
[update.sh](../kultura_bot/deploy/update.sh):

1. забирает последний коммит `main` (`git fetch --depth 1`);
2. тот же, что в `/opt/kultura-bot/deployed`, — ничего не делает;
3. в `kultura_bot/` ничего не менялось (правка только сайта) — запоминает новую версию, бот
   не перезапускается;
4. менялось — обновляет код, зависимости, службы и сам скрипт, перезапускает бота и только
   после этого запоминает версию: сбой посередине — повтор через 2 минуты.

Перезапуск не теряет вопросы молча: начатые ответы доводятся до конца, ждавшие очереди после
запуска получают «Ответ на прошлый вопрос прервался… Повторите вопрос» (раздел 10).

### 4. Ключ сервера бота

Статический MCP-токен ([mcp.md](mcp.md), «Статические токены»): `kmcp_…`, все разделы, полный
режим, без срока, имя «Бот @MCPkulturabot — сервер в Амстердаме». Выпускает его кнопка
«Команда установки» от имени нажавшего администратора; id — в `settings`
(`kultura_bot_engine_token`). На сайте хранится только хэш, целиком ключ — в команде установки
и в `/etc/kultura-bot.env` на сервере.

Что он открывает:

- **MCP** (`/mcp`, `/mcp/<раздел>`) — инструменты, как у агентов владельца: те же проверки
  аргументов, лимиты (120 вызовов в минуту на ключ) и журнал вызовов (клиент — имя ключа).
- **API бота** (`/api/bot/*`) — только этому ключу (`site_api.verify_engine`): другой MCP-токен
  получает 401 — агент не может забрать секреты бота.

Ключ виден в списке «Статические токены» той же страницы, его можно отозвать там. Отключение
или снятие админства у выпустившего администратора отзывает ключ
(`routes/auth._revoke_agent_access`): бот замолкает до новой команды установки.

### 5. Настройки с сайта

Сервер бота раз в 30 секунд (`CONFIG_EVERY_S`) спрашивает `GET /api/bot/config`: токен
Telegram, имя бота, ключ Anthropic, пауза.

- Нет токена или ключа — состояние «ждёт настройки», сообщения не забираются: если токеном
  пользуется другая программа (старый бот), она работает как работала.
- Пауза — бот молчит (сообщения не забираются).
- Ключ Anthropic сменился — сервер сразу проверяет его бесплатным запросом списка моделей;
  ошибка (ключ не принят, нет доступа к модели) видна в строке состояния на странице.
- Токен сменился — новый клиент Telegram: `getMe`, снятие вебхука (без сброса очереди),
  команды `/new` и `/help`, приём сообщений сам (getUpdates, ожидание 25 с).
- Сайт не ответил — сервер работает на последних настройках; не ответил при запуске — ждёт.
- Сайт отверг ключ сервера (новая команда установки, ключ отозван) — бот замолкает, в журнале
  сервера: «Сайт не принял ключ сервера бота…».

### 6. Кто может писать боту

Только администраторы сайта, привязавшие свой Telegram. Списков id нет (решение владельца
2026-10-18: «не буду вписывать айди каждого пользователя руками»):

1. Администратор на `/admin/mcp`, раздел «Бот», жмёт «Подключить мой Telegram». Страница
   показывает ссылку `https://t.me/MCPkulturabot?start=<код>`. Код — `secrets.token_urlsafe(12)`
   (16 символов `[A-Za-z0-9_-]`, перебором не угадать), одноразовый, живёт 15 минут
   (`LINK_CODE_TTL_S = 900`) и привязан к администратору, который нажал кнопку.
2. Он открывает ссылку и жмёт «Старт». Сервер бота получает `/start <код>` и передаёт сайту
   (`POST /api/bot/link` -> `access.link_by_code`); бот отвечает «Готово: вы подключены как …».
   Страница видит новую привязку сама (проверяет каждые 5 секунд 5 минут).
3. Кто пишет, сервер бота спрашивает сайт (`GET /api/bot/actor/<id>` -> `access.actor_for`):
   привязанный **активный администратор** или никто. Ответ помнится минуту
   (`ACTOR_CACHE_S`), а перед каждым ответом спрашивается заново; инструменты сайт проверяет
   ещё и на каждом вызове. Снять привязку — кнопка «Отключить» в таблице. Отключение
   аккаунта, снятие флага администратора и удаление аккаунта снимают и его привязки вместе с
   неиспользованными ссылками (`routes/auth._revoke_agent_access` ->
   `store.delete_links_for_user`): возврат флага старый Telegram не оживляет — как MCP-токены.

Незнакомцу в личке бот отвечает одной фразой «Это закрытый бот…» не чаще раза в час
(`REFUSAL_EVERY_S = 3600`) и ничего не тратит: Claude не вызывается. В группе — молчит.

**От чьего имени работают инструменты.** Все вызовы идут по ключу сервера бота, то есть от
имени администратора, выпустившего ключ; в журнале вызовов — клиент «Бот @MCPkulturabot —
сервер в Амстердаме». Кто именно спросил, модель знает из служебной строки вопроса (раздел 7):
бот отвечает только администраторам, а у всех администраторов одинаковые права на сайте.

### 7. Сообщение -> ответ

1. Личка — всегда. Группа — если `ANSWER_IN_GROUPS = True` и к боту обратились: `@MCPkulturabot`
   в тексте, ответ на сообщение бота, команда `/…@MCPkulturabot`. В группе бот отвечает
   ответом на сообщение.
2. Команды: `/start <код>` — привязка; `/new` — новый диалог (встаёт в очередь чата: ответ,
   который ещё пишется, не вернёт старый диалог); `/help` — что умеет бот.
3. Вопрос — текст, фото, PDF или картинка файлом. Предел файла: картинка — 3,75 МБ (Claude API
   принимает картинку до 5 МБ в base64), PDF — `INPUT_FILE_MAX_BYTES` = 10 МБ. Больше или не
   скачался — бот отвечает без файла и говорит об этом; файл другого вида (Word, Excel) — «Этот
   файл я не читаю…», ответ по тексту сообщения.
4. Очередь: в одном чате вопросы идут по порядку, разных чатов одновременно — не больше
   `MAX_PARALLEL_DIALOGS` = 2. Вопрос записывается в базу сразу (`queued`), ещё в очереди:
   перезапуск, пока он ждёт, не потеряет его молча (раздел 10).
5. Пока модель думает, в чате «печатает…» (обновляется каждые 4,5 с).
6. К вопросу бот приписывает служебную строку, например
   `[19.10.2026 14:05 МСК · рабочий день бара 2026-10-19 · пишет Владелец (owner)]`: модель знает
   дату, рабочий день бара (до 06:00 МСК идёт прошлый) и кто спрашивает. Строка стоит в самом
   сообщении, а не в системном промпте, — иначе каждый вопрос ломал бы кэш (раздел 8).
7. Ответ модели (Markdown) переводится в HTML Telegram (`formatting.py`): `**жирный**`, таблицы и
   код — моноширинным блоком (и однострочный «```ls -la```»), ссылки; длинный — частями до 3500
   символов по абзацам, строка кода длиннее части режется, блок кода не рвётся без нужды.
   Telegram не принял разметку — та же часть уходит простым текстом; попросил подождать (429) —
   бот ждёт до 30 с и повторяет.
8. Сайт не ответил (вопрос о доступе или каталог) — «Сайт сейчас не отвечает, без него я не
   вижу данных. Повторите вопрос через пару минут».

### 8. Разговор с Claude (`agent.run_turn`)

```
история диалога + вопрос
 -> запрос к Claude
 -> модель вызвала инструменты (stop_reason tool_use): бот исполняет их на сайте, все
    результаты — одним сообщением, снова запрос — пока модель не ответит текстом
 -> ответ (текст последнего шага) + дописанная история
```

Запрос идёт потоком (`client.beta.messages.stream`, итог шага — `get_final_message`): на
`xhigh` шаг бывает долгим, а поток не упирается в таймаут HTTP. Бот ждёт шаг целиком — в
Telegram ответ уходит готовым.

Параметры запроса (`agent.request_params`):

| Параметр | Значение | Зачем |
|---|---|---|
| `model` | `MODEL` = `claude-opus-5-5` | умолчание Anthropic для агентов |
| `output_config.effort` | `EFFORT` = `xhigh`, агентам `AGENT_EFFORT` = `xhigh` (решение владельца 2026-10-20; умолчание Opus 5.5 — `medium`) | глубина размышлений и проверок; выше — дольше и дороже: на `xhigh` рассуждения и ответы заметно длиннее |
| `thinking` | `adaptive` (у Opus 5.5 всегда включено) + `block_binding.prefix_mismatch_behavior: drop_block` | рассуждения привязаны к неизменному началу разговора; если начало всё же разошлось, Claude отбрасывает их, а не отвечает ошибкой |
| `max_tokens` | `MAX_TOKENS` = 64 000 на шаг | шаг — рассуждения плюс текст или вызовы инструментов до следующего вызова; на `xhigh` рассуждения длинные |
| `system` | собранный промпт с точкой кэша | раздел 9 |
| `cache_control` (верхний уровень) | `ephemeral` | автоматическая точка кэша на хвосте разговора: следующий шаг читает всё начало из кэша |
| `tools` | поиск, видимые сразу, отложенные | раздел 9 |
| `context_management` | `clear_tool_uses_20250919`: вход больше `CONTEXT_CLEAR_AT_TOKENS` = 80 000 токенов — Anthropic вычищает старые ответы инструментов, оставляя `CONTEXT_KEEP_TOOL_RESULTS` = 6 последних; результаты поиска инструментов не трогает | длинный диалог не дорожает без конца |
| `fallbacks` | `"default"` (`REFUSAL_FALLBACK = True`) | ложный отказ классификатора безопасности — ответ запасной модели Anthropic в том же запросе |
| `speed` | `"fast"` (`FAST_MODE = True`, решение владельца 2026-10-20) | быстрый режим: та же модель, вывод до 2,5 раза быстрее, цена × 2 (раздел 11) |
| `betas` | `thinking-binding-controls-2026-08-01`, `context-management-2025-06-27`, `server-side-fallback-2026-07-01`, `fast-mode-2026-02-01` | бета-параметры выше; быстрому режиму Opus 5.5 бета не нужна, а запасным Opus 5 и Opus 4.8 — нужна |

`block_binding`, `context_management` и `fallbacks` — бета. Если Anthropic отвергнет одну из них
(ошибка 400 с её именем в тексте), бот повторяет запрос без неё и до перезапуска больше её не
шлёт (`agent.OPTIONAL_FEATURES`); в журнале сервера — предупреждение, человек получает ответ.

**Быстрый режим.** Запрос с `speed: "fast"` идёт без повторов SDK (`max_retries=0`). Быстрый режим
не ответил — 429 (у него свой предел частоты), 5xx или 529 (в том числе ошибкой посреди потока),
обрыв связи или отказ именно в нём (400 или 403 со словами speed / fast mode) — тот же шаг сразу
повторяется на обычной скорости с обычными повторами SDK, и `FAST_COOLDOWN_S` = 600 с бот
быстрый режим не просит (`agent.fast_mode_on`; в журнале сервера — «быстрый режим не ответил
(…) — 10 мин на обычной скорости»). Человек ошибки не видит, ответ просто медленнее. Пауза, а
не попытка на каждом шаге: запросы разных скоростей не делят кэш, каждая смена скорости —
промах кэша. Какая скорость была у шага, говорит `usage.speed` ответа — по нему считается цена.
`FAST_MODE = False` — всегда обычная скорость.

**Смена модели посреди ответа.** Запасная модель (`fallbacks`) может подхватить ответ посреди
вывода: в потоке остаются начало ответа отказавшей модели, блок `fallback` и продолжение. В
историю и на исполнение идёт то, что разрешает документация Anthropic («Echoing fallback turns
back»): до последнего блока `fallback` — только текст и парные блоки серверных инструментов;
рассуждения и вызовы инструментов отказавшей модели не исполняются и назад не отправляются
(`agent.after_fallback`).

**История только дописывается.** Блоки ответа сохраняются ровно так, как их прислал API
(`to_dict`), и ничего в истории не правится: Claude проверяет, что рассуждения модели
(thinking) лежат в том же разговоре, в котором получены, а кэш работает только на неизменном
начале запроса. Поэтому системный промпт и список инструментов на весь диалог одни, а всё
переменное (время, кто пишет) — в сообщении человека.

Пределы:

- `MAX_TOOL_ROUNDS` = 30 шагов с инструментами на вопрос (агенту `AGENT_MAX_TOOL_ROUNDS` = 40).
  Исчерпаны — на новые вызовы модель получает отказ «лимит шагов», а последний запрос идёт с
  `tool_choice: none`: модель отвечает тем, что уже узнала, и говорит, чего не проверила.
- `pause_turn` (серверный инструмент не уложился в шаг) — запрос повторяется как есть, не
  больше 5 раз подряд.
- `stop_reason: max_tokens` — к ответу дописывается «(ответ обрезан…)»; `refusal` — «Модель
  отказалась отвечать на этот вопрос… Переформулируйте его».
- Шаг оборвался на пределе длины посреди вызова инструмента — вызов не выполняется: в историю
  на каждый такой `tool_use` пишется ответ-ошибка (иначе следующий запрос диалога Claude
  отклонит), последний запрос — без инструментов.

### 9. Инструменты и агенты

**Каталог** (`tools.load_catalog`) сервер бота собирает у сайта по MCP и помнит
`CATALOG_TTL_S` = 600 с:

| Что | Откуда |
|---|---|
| правила сервиса | `initialize` полного коннектора `/mcp` — те же `instructions`, что получают агенты по MCP |
| инструменты бота | `tools/list` на `/mcp` |
| инструменты агента | `tools/list` на `/mcp/<раздел>` по каждому его разделу (объединение) |
| правила разделов агента | `common_instructions(domain)` по каждому его разделу |

Системный промпт бота = `prompts/bot.md` + список агентов (имя, название, когда поручать) +
правила сервиса. Инструменты (`tools.build_toolset`), порядок неизменен:

1. `tool_search_tool_regex` — серверный поиск Anthropic по описаниям инструментов;
2. видимые сразу: `ALWAYS_LOADED_TOOLS` (`common_chart_send`, `common_whoami`,
   `common_bars_reference`, `common_docs_read`, `common_instructions`) и `ask_agent`;
3. остальные инструменты сайта (~240) с `defer_loading: true`: модель находит их поиском, в её
   контекст попадают только найденные.

`HIDDEN_TOOLS` боту не даются (`common_notify_owner`: бот и так пишет в чат). Сайт выложил
новые инструменты или правила — у каталога новый отпечаток, диалоги начинаются заново
(раздел 10).

**Вызов** — `tools/call` на `/mcp` с ключом сервера бота (`site.call_tool`, таймаут 240 с:
живые запросы в iiko идут минуту-две). Сайт сам проверяет аргументы, держит лимиты и пишет
журнал; ответ-ошибку модель получает ошибкой инструмента, недоступный сайт — «Сайт не
выполнил вызов: …». Режим — полный: изменяющие инструменты есть, а правило в `prompts/bot.md` —
ничего не менять и не отправлять без прямой просьбы, перед необратимым пересказать, что
изменится, и дождаться «да».

`common_chart_send`: `chat_id` подставляет бот — чат разговора, что бы ни прислала модель (из
данных не уйдёт в чужой чат). Картинку рисует и отправляет сайт токеном со страницы.

`ask_agent(agent, task)` — поручение агенту: отдельный разговор, системный промпт =
`prompts/agent.md` + `agents/<имя>.md` + правила его разделов + правила сервиса; инструменты —
только его разделов и общие `common_`, без `ask_agent`; усилие `AGENT_EFFORT`; к задаче
приписывается та же служебная строка. Отчёт (не длиннее `AGENT_ANSWER_MAX_CHARS` = 20 000
символов) возвращается боту результатом инструмента, бот пересказывает его коротко.

| `name` | Название | Разделы (`domains`) | Когда бот поручает |
|---|---|---|---|
| `analyst` | Аналитик | `stocks`, `analytics` | сводки по остаткам и заказам, продажам и планам, розливу и фасовке, гостям |
| `payroll` | Зарплаты и график | `staff` | зарплата и KPI за месяц, часы и смены, касса и штрафы, проверка перед закрытием месяца |
| `content` | Контент | `content` | черновики контент-плана, проверка недели, отзывы гостей |

Новый агент — файл `kultura_bot/agents/<имя>.md`:

```
---
name: supplies
title: Закупки
domains: stocks
description: Когда поручать задачу этому агенту — бот видит это в своих инструкциях.
---
Правила агента обычным текстом.
```

`name` — латиница, цифры, «_», 2–31 символ; `domains` — через запятую из `content`, `stocks`,
`analytics`, `staff`. Ошибка в заголовке называет файл, и тест `test_agents_and_prompts_load`
падает до выкладки.

### 10. Диалог и память

Своя база сервера бота — `/var/lib/kultura-bot/bot.db` (`engine/store.py`). Сайт её не видит:
история разговоров остаётся на сервере бота.

| Таблица | Что |
|---|---|
| `dialogs` | текущий диалог чата: отпечаток, начало, время последнего вопроса, число вопросов, история Messages API как есть |
| `jobs` | вопросы: `queued` (ждёт очереди) -> `running` -> `done` / `error` / `interrupted`; хранятся 30 дней |
| `usage` | расход по дням (МСК) и моделям — для дневного предела |

Диалог чата продолжается, пока выполнены все три условия:

- с прошлого вопроса прошло меньше `DIALOG_IDLE_MINUTES` = 120 минут;
- инструкции и инструменты те же: отпечаток = первые 16 символов sha256 от системного промпта и
  списка инструментов (`config.fingerprint`), он хранится с диалогом;
- история короче 16 МБ (`MAX_DIALOG_BYTES`; каждый запрос отправляет её целиком, Claude API
  принимает до 32 МБ, PDF предельного размера в base64 — 13,3 МБ).

Иначе — новый диалог, и ответ начинается пометкой: «Прошло много времени с прошлого вопроса,
начинаю новый диалог.» (`NEW_DIALOG_NOTICE`), «Обновились инструкции бота — начинаю новый
диалог.» или «Диалог стал слишком длинным — начинаю новый.». `/new` — новый диалог сразу.
Ответ упал с ошибкой 400 (битая история) — диалог стирается, человек получает «Диалог начат
заново — повторите вопрос».

Остановка службы (обновление, перезагрузка сервера): начатые ответы доводятся до конца (до
90 с), новые вопросы в эти секунды получают «Сервер перезапускается — повторите вопрос через
минуту». Ждавшие очереди и оборванные (`running` при запуске) помечаются `interrupted`, а
после запуска чат получает «Ответ на прошлый вопрос прервался: сервер перезапускался.
Повторите вопрос» — один раз на чат, если вопросу меньше 30 минут.

### 11. Деньги

Цена каждого шага модели (`claude.cost_usd`) — по токенам из `usage` ответа API:

```
цена шага ($) = (вход × P_вход + выход × P_выход + чтение_кэша × P_чтение + запись_кэша × P_запись) / 1 000 000
                × 2, если шаг прошёл в быстром режиме (usage.speed = "fast")
```

округляется до $0,000001. Цены за 1 млн токенов (`PRICES_PER_MTOK`, прайс Anthropic, октябрь
2026):

| Модель | Вход | Выход | Чтение кэша | Запись кэша (5 мин) |
|---|---|---|---|---|
| `claude-opus-5-5` | 4,00 | 20,00 | 0,20 | 5,00 |
| `claude-sonnet-5-5` | 2,00 | 10,00 | 0,20 | 2,50 |
| `claude-haiku-5-5` | 0,10 | 0,50 | 0,01 | 0,125 |
| `claude-opus-5`, `claude-opus-4-8` (запасные модели) | 5,00 | 25,00 | 0,50 | 6,25 |

Быстрый режим — все четыре цены × `FAST_PRICE_MULTIPLIER` = 2: Opus 5.5 — $8 вход / $40 выход,
Opus 5 и Opus 4.8 — $10 / $50; наценки кэша считаются поверх (у Opus 5.5 чтение кэша — $0,40,
запись — $10). Источник — прайс Anthropic, «Fast mode pricing».

Модель берётся из ответа (`response.model`): если ответила запасная модель, шаг считается по
её цене. Имя ищется по самому длинному совпавшему началу (`claude-opus-5-5-…` — не
`claude-opus-5`); модель не из таблицы считается по цене `MODEL`.

Пример (Opus 5.5): шаг с 3 000 новых токенов входа, 40 000 токенов из кэша и 600 токенами
ответа стоит (3 000 × 4 + 600 × 20 + 40 000 × 0,20) / 1 000 000 = (12 000 + 12 000 + 8 000) /
1 000 000 = $0,032. Вопрос в четыре шага — около $0,13. В быстром режиме тот же шаг — $0,064.
На `xhigh` модель думает дольше, чем на `medium`: токенов вывода больше, и вопрос обходится
дороже — это сдерживает дневной предел ниже.

Дневной предел `DAILY_BUDGET_USD` = $15: перед каждым шагом сервер бота сверяет сумму за
московские сутки (своя таблица `usage`) с пределом; достигнут — в чат «Дневной предел расхода
на Claude исчерпан: X $ из 15 $… Бот снова ответит после полуночи МСК». Шаг, начатый до
предела, доводится до конца, поэтому предел может быть превышен на один шаг. `0` — без
предела.

Расход уходит сайту в отчёте (раздел 12) и копится в `bot_usage` (`mcp.db`) по дням и моделям
(запросы, токены, $); страница показывает «сегодня» и «за 30 дней». Отчёт не дошёл — расход
копится на сервере бота до следующего. Это оценка по токенам: источник истины — счёт в консоли
Anthropic (там же можно поставить свой предел расходов на ключ).

### 12. Состояние и ошибки

Сервер бота отчитывается сайту (`POST /api/bot/report`) при каждом изменении состояния и не
реже раза в минуту (`HEARTBEAT_S`): состояние, последняя ошибка Claude, имя бота и расход с
прошлого отчёта. Сайт пишет состояние в `settings` (`kultura_bot_status`) с временем прихода.
Страница показывает первой строкой раздела:

| Состояние | Что на странице | Что делать |
|---|---|---|
| ключ не выпускали | «Бот ещё не установлен: нажмите «Команда установки»…» | раздел 2 |
| ключ отозван | «Ключ сервера бота отозван — бот молчит…» | новая команда установки |
| ключ выпущен, отчётов ещё нет | «Сервер бота ещё не отзывался: выполните команду установки… journalctl -u kultura-bot -n 50» | выполнить команду; уже выполнили — журнал на сервере |
| `starting` | «Бот запускается…» | — |
| `waiting` | «Бот ждёт настройки: нет токена бота / нет ключа Claude API» | вставить и сохранить |
| `paused` | «Бот на паузе» | снять флажок «Пауза» |
| `running` | «Бот @MCPkulturabot работает: слушает Telegram и отвечает» | — |
| `running` + `claude_error` | «…слушает Telegram, но Claude не ответил: <текст ошибки>» — ключ не принят, отказ (403), кончились деньги, нет связи с Anthropic; держится, пока следующий ответ не получится | по тексту |
| `conflict` | «Конфликт: токеном бота пользуется другая программа (старый бот?)…» | остановить другую программу или выпустить новый токен |
| `error` | текст ошибки: Telegram не принимает токен, нет связи с Telegram | по тексту |
| `stopped` | «Сервер бота остановлен (время)» | `systemctl start kultura-bot` на сервере |
| отчёта нет дольше 3 минут (`STALE_AFTER_S`) | «Сервер бота давно не отзывался… проверьте сервер в Амстердаме (systemctl status kultura-bot)» | проверить сервер |

Новая команда установки стирает прежнее состояние: до первого отчёта нового сервера —
«ещё не отзывался».

Ошибки Anthropic человек получает понятным текстом (`claude.describe_error`):

| Ошибка | Текст (суть) |
|---|---|
| 401 | «Anthropic не принял ключ API» — новый ключ на странице |
| 403 | «Anthropic отказал (403): … У ключа нет доступа к модели или к организации — проверьте ключ в консоли Anthropic» |
| нет связи, таймаут | «Нет связи с Anthropic… Повторите через минуту» |
| 429 | «Anthropic ограничил частоту запросов» — повторить через минуту |
| 529 | «Claude сейчас перегружен» — повторить через пару минут |
| 5xx | «Сбой на стороне Anthropic» |
| мало денег на счёте (402, billing) | «На счёте Anthropic кончились деньги» — пополнить в консоли |
| другая 400 | текст ошибки + «Диалог начат заново — повторите вопрос» |
| ошибка посреди потока (событие error при HTTP 200) | по её типу (`claude.api_status`): `overloaded_error` — как 529, `api_error` — как 5xx, `rate_limit_error` — как 429, `invalid_request_error` — как 400 |

Сбои быстрого режима человек не видит: шаг уходит на обычную скорость (раздел 8).

Токен, ключ Anthropic и ключ сервера в тексты ошибок для чата и страницы не попадают: всё, что
пришло из исключения, проходит `claude.scrub` — секреты заменяются на «***». В журнал сервера
ошибки связи с Telegram пишутся только видом исключения: в адресе запроса Telegram есть токен.

### 13. Страница «Доступ агентов», раздел «Бот @MCPkulturabot»

### 14. Что сделать владельцу (один раз)

1. Создать ключ Claude API: console.anthropic.com -> API Keys -> Create Key.
2. Открыть `https://beerkultura.ru/admin/mcp` -> «Бот @MCPkulturabot»: вставить ключ (и токен
   бота, если подсказка под полем говорит «Нет») -> «Сохранить».
3. Там же — «Команда установки» -> «Скопировать». Зайти на сервер в Амстердаме под root
   (`ssh root@<адрес сервера>`), вставить команду, Enter. Через минуту строка состояния —
   «Бот @MCPkulturabot работает».
4. Если токеном бота ещё пользуется старая программа (строка «Конфликт») — остановить её; не
   знаете, где она, — в @BotFather `/revoke` выпустить новый токен и вставить его на странице:
   старая программа отключится сама.
5. «Подключить мой Telegram» -> «Открыть Telegram и нажать «Старт»» -> «Старт». Бот ответит
   «Готово: вы подключены как …».
6. Задать боту вопрос. Другие администраторы подключаются так же, каждый со своего входа на сайт.

### Что сломается при неверной правке

- Править историю диалога (удалять или менять старые сообщения, переставлять блоки) или менять
  системный промпт и порядок инструментов посреди диалога — Claude отбросит рассуждения модели
  (или ответит 400), кэш перестанет работать: ответы хуже и дороже. Всё переменное — только в
  сообщении человека.
- Положить токен или ключ в `settings.py` или в любой файл репозитория — репозиторий публичный.
- Импортировать в `kultura_bot/engine/` код сайта (`core`, `routes`, Flask) — на сервере бота его
  нет, служба не запустится (это ловит `test_engine_does_not_import_site_code`).
- Пустить в `/api/bot/*` любой MCP-токен — агент заберёт токен бота и ключ Anthropic.
- Убрать проверку администратора в `access.actor_for` — бот ответит кому угодно данными владельца.
- Не подставлять `chat_id` в `common_chart_send` — модель по «команде» из данных отправит график в
  чужой чат.
- Убрать дневной предел — зациклившийся агент потратит деньги.
- Добавить инструмент сайта, которого у бота быть не должно, и не внести его в `HIDDEN_TOOLS` —
  бот его получит: у бота все инструменты полного коннектора MCP.
- Сломать `deploy/update.sh` или службы — сервер бота перестанет обновляться (или перезапускаться)
  до ручного запуска новой команды установки; проверка — `bash -n` и журнал
  `journalctl -u kultura-bot-update`.
