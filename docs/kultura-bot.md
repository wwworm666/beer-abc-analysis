# Бот @MCPkulturabot (`kultura_bot/`)

## Что это

ИИ-помощник владельца сети «Культура» в Telegram. Отвечает по данным сайта: у него те же
инструменты, что у ИИ-агентов по MCP ([mcp.md](mcp.md)), и каждый вызывает настоящий расчёт
страницы от имени администратора, который пишет боту. Работает на сервере вместе с сайтом (в
контейнере `app`), думает через Claude API по отдельному ключу Anthropic. Большие задачи по
одному разделу поручает агентам: «Аналитик», «Зарплаты и график», «Контент». Графики присылает
картинкой с кнопкой «Открыть интерактивно» ([tg-miniapp.md](tg-miniapp.md)).

Решение владельца 2026-10-19: бот — отдельная папка внутри репозитория, все настройки и
инструкции бота и его агентов лежат в проекте, отдельный ключ Anthropic для бота — нормально.
До этого бот был внешней программой: его кода в репозитории не было, и правила для него
(например, «графики — только через сайт») до него не доходили.

**Где что менять:**

| Что | Где | Когда подействует |
|---|---|---|
| Как бот отвечает: тон, формат, правила | `kultura_bot/prompts/bot.md` | после выкладки; идущие диалоги начнутся заново с пометкой «Обновились инструкции бота» |
| Общие правила всех агентов, формат отчёта боту | `kultura_bot/prompts/agent.md` | после выкладки |
| Агент: разделы, когда поручать, правила | `kultura_bot/agents/<имя>.md` (новый файл — новый агент) | после выкладки |
| Модель, усилие, пределы шагов, дневной предел расхода, диалог, графики | `kultura_bot/settings.py` | после выкладки |
| Токен бота, ключ Anthropic, прокси, пауза | страница `/admin/mcp`, раздел «Бот @MCPkulturabot» | сразу, без выкладки |
| Кто может писать боту | там же: «Подключить мой Telegram», «Отключить» | сразу |
| Правила инструментов сайта (общие для бота и MCP-агентов) | `INSTRUCTIONS` в `core/mcp/tools/<раздел>.py` | после выкладки |

Секретов в репозитории нет: он публичный, токен и ключ оттуда забрал бы кто угодно.

## Как работает

### 1. Запуск

- `app.py` зовёт `kultura_bot.start(app)` в каждом gunicorn-воркере. Работает бот ровно в
  одном — том, что взял эксклюзивный flock на `data/.kultura_bot.lock` (как опрос бота
  проверки открытия). Воркер умер или перезапустился — ОС снимает лок, бота подхватывает
  следующий воркер при старте.
- Бот слушает Telegram, только когда на странице есть **и** токен бота, **и** ключ Anthropic, и
  бот не на паузе. До этого он не забирает сообщения вовсе: если токеном пользуется другая
  программа (старый бот), она работает как работала.
- Ключи появились — бот снимает вебхук (без сброса очереди сообщений), ставит команды `/new` и
  `/help` и забирает сообщения сам (getUpdates, ожидание 25 с). Вебхук не годится: входящие
  соединения от Telegram до сервера режет ТСПУ ([open-check-bot.md](open-check-bot.md),
  «Блокировки»).
- `KULTURA_BOT=0` в окружении — не запускать (тесты, локальные скрипты).
- Сбой запуска бота сайт не роняет: ошибка пишется в журнал сервера («бот не запустился»), лок
  отпускается — бота подхватит другой воркер, сайт работает как обычно.

### 2. Кто может писать боту

Только администраторы сайта, привязавшие свой Telegram. Списков id нет (решение владельца
2026-10-18: «не буду вписывать айди каждого пользователя руками»):

1. Администратор на `/admin/mcp`, раздел «Бот», жмёт «Подключить мой Telegram». Страница
   показывает ссылку `https://t.me/MCPkulturabot?start=<код>`. Код — `secrets.token_urlsafe(12)`
   (16 символов `[A-Za-z0-9_-]`, перебором не угадать), одноразовый, живёт 15 минут
   (`LINK_CODE_TTL_S = 900`) и привязан к администратору, который нажал кнопку.
2. Он открывает ссылку и жмёт «Старт». Бот получает `/start <код>` и отвечает «Готово: вы
   подключены как …». Страница видит новую привязку сама (проверяет каждые 5 секунд 5 минут).
3. Права проверяются на каждом сообщении (`access.actor_for`) и на каждом вызове инструмента
   (`core/mcp/bridge`): снять флаг администратора или отключить аккаунт — бот перестаёт
   отвечать сразу. Снять привязку — кнопка «Отключить» в таблице.

Незнакомцу в личке бот отвечает одной фразой «Это закрытый бот…» не чаще раза в час
(`REFUSAL_EVERY_S = 3600`) и ничего не тратит: Claude не вызывается. В группе — молчит.

### 3. Сообщение -> ответ

1. Личка — всегда. Группа — если `ANSWER_IN_GROUPS = True` и к боту обратились: `@MCPkulturabot`
   в тексте, ответ на сообщение бота, команда `/…@MCPkulturabot`. В группе бот отвечает
   ответом на сообщение.
2. Команды: `/start <код>` — привязка; `/new` — новый диалог; `/help` — что умеет бот.
3. Вопрос — текст, фото, PDF или картинка файлом. Предел файла: картинка — 3,75 МБ (Claude API
   принимает картинку до 5 МБ в base64), PDF — `INPUT_FILE_MAX_BYTES` = 10 МБ. Больше или не
   скачался — бот отвечает без файла и говорит об этом.
4. Очередь: в одном чате вопросы идут по порядку, разных чатов одновременно — не больше
   `MAX_PARALLEL_DIALOGS` = 2.
5. Пока модель думает, в чате «печатает…» (обновляется каждые 4,5 с).
6. К вопросу бот приписывает служебную строку, например
   `[19.10.2026 14:05 МСК · рабочий день бара 2026-10-19 · пишет Владелец (owner)]`: модель знает
   дату, рабочий день бара (до 06:00 МСК идёт прошлый) и кто спрашивает. Строка стоит в самом
   сообщении, а не в системном промпте, — иначе каждый вопрос ломал бы кэш (раздел 4).
7. Ответ модели (Markdown) переводится в HTML Telegram (`formatting.py`): `**жирный**`, таблицы и
   код — моноширинным блоком, ссылки; длинный — частями до 3500 символов по абзацам, блок кода
   не рвётся без нужды. Telegram не принял разметку — та же часть уходит простым текстом.

### 4. Разговор с Claude (`agent.run_turn`)

```
история диалога + вопрос
 -> запрос к Claude
 -> модель вызвала инструменты (stop_reason tool_use): бот исполняет их, все результаты —
    одним сообщением, снова запрос — пока модель не ответит текстом
 -> ответ (текст последнего шага) + дописанная история
```

Параметры запроса (`agent.request_params`):

| Параметр | Значение | Зачем |
|---|---|---|
| `model` | `MODEL` = `claude-opus-5-5` | умолчание Anthropic для агентов |
| `output_config.effort` | `EFFORT` = `medium`; агентам `AGENT_EFFORT` = `high` | глубина размышлений и проверок; выше — дольше и дороже |
| `thinking` | `adaptive` (у Opus 5.5 всегда включено) + `block_binding.prefix_mismatch_behavior: drop_block` | рассуждения привязаны к неизменному началу разговора; если начало всё же разошлось, Claude отбрасывает их, а не отвечает ошибкой |
| `max_tokens` | `MAX_TOKENS` = 16 000 на шаг | шаг — кусок между вызовами инструментов |
| `system` | собранный промпт с точкой кэша | раздел 5 |
| `cache_control` (верхний уровень) | `ephemeral` | автоматическая точка кэша на хвосте разговора: следующий шаг читает всё начало из кэша |
| `tools` | поиск, видимые сразу, отложенные | раздел 5 |
| `context_management` | `clear_tool_uses_20250919`: вход больше `CONTEXT_CLEAR_AT_TOKENS` = 80 000 токенов — Anthropic вычищает старые ответы инструментов, оставляя `CONTEXT_KEEP_TOOL_RESULTS` = 6 последних; результаты поиска инструментов не трогает | длинный диалог не дорожает без конца |
| `fallbacks` | `"default"` (`REFUSAL_FALLBACK = True`) | ложный отказ классификатора безопасности — ответ запасной модели Anthropic в том же запросе |
| `betas` | `thinking-binding-controls-2026-08-01`, `context-management-2025-06-27`, `server-side-fallback-2026-07-01` | бета-параметры выше |

Последние три возможности — бета. Если Anthropic отвергнет одну из них (ошибка 400 с её именем
в тексте), бот повторяет запрос без неё и до перезапуска больше её не шлёт
(`agent.OPTIONAL_FEATURES`); в журнале сервера — предупреждение, человек получает ответ.

**История только дописывается.** Блоки ответа сохраняются ровно так, как их прислал API
(`to_dict`), и ничего в истории не правится: Claude проверяет, что рассуждения модели
(thinking) лежат в том же разговоре, в котором получены, а кэш работает только на неизменном
начале запроса. Поэтому системный промпт и список инструментов на весь диалог одни, а всё
переменное (время, кто пишет) — в сообщении человека.

Пределы:

- `MAX_TOOL_ROUNDS` = 30 шагов с инструментами на вопрос (агенту `AGENT_MAX_TOOL_ROUNDS` = 40).
  Исчерпаны — на новые вызовы модель получает отказ «лимит шагов», а последний запрос идёт с
  `tool_choice: none`: модель отвечает тем, что уже узнала, и говорит, чего не проверила.
- `pause_turn` (серверный инструмент не уложился в шаг) — запрос повторяется как есть, не
  больше 5 раз подряд.
- `stop_reason: max_tokens` — к ответу дописывается «(ответ обрезан…)»; `refusal` — «Модель
  отказалась отвечать на этот вопрос… Переформулируйте его».

### 5. Инструменты и агенты

Системный промпт бота = `prompts/bot.md` + список агентов (имя, название, когда поручать) +
общие правила сервиса для полного подключения (`core/mcp/registry.instructions_for(None)` — те
же, что получают агенты по MCP).

Инструменты (`tools.tool_defs`), порядок неизменен:

1. `tool_search_tool_regex` — серверный поиск Anthropic по описаниям инструментов;
2. видимые сразу: `ALWAYS_LOADED_TOOLS` (`common_chart_send`, `common_whoami`,
   `common_bars_reference`, `common_docs_read`, `common_instructions`) и `ask_agent`;
3. остальные инструменты сайта (~240) с `defer_loading: true`: модель находит их поиском, в её
   контекст попадают только найденные.

Инструменты сайта — из `core/mcp/registry`, вызываются через `core/mcp/bridge.execute` от
имени администратора, который пишет: те же проверки аргументов, кэш тяжёлых ответов, лимиты и
журнал, что у MCP. В журнале страницы «Доступ агентов» — клиент «Бот @MCPkulturabot»,
коннектор `telegram`, токен `tg_<id в Telegram>`. Режим — полный: изменяющие инструменты есть,
а правило в `prompts/bot.md` — ничего не менять и не отправлять без прямой просьбы, перед
необратимым пересказать, что изменится, и дождаться «да». `HIDDEN_TOOLS` боту не даются
(`common_notify_owner`: бот и так пишет в чат).

`common_chart_send`: `chat_id` подставляет бот — чат разговора, что бы ни прислала модель (из
данных не уйдёт в чужой чат).

`ask_agent(agent, task)` — поручение агенту: отдельный разговор, системный промпт =
`prompts/agent.md` + `agents/<имя>.md` + правила его разделов (`registry.domain_instructions`) +
общие правила; инструменты — только его разделов и общие `common_`, без `ask_agent`; усилие
`AGENT_EFFORT`; к задаче приписывается та же служебная строка. Отчёт (не длиннее
`AGENT_ANSWER_MAX_CHARS` = 20 000 символов) возвращается боту результатом инструмента, бот
пересказывает его коротко. В журнале — `ask_agent:<имя>`.

| `name` | Название | Разделы (`domains`) | Когда бот поручает |
|---|---|---|---|
| `analyst` | Аналитик | `stocks`, `analytics` | сводки по остаткам и заказам, продажам и планам, розливу и фасовке, гостям |
| `payroll` | Зарплаты и график | `staff` | зарплата и KPI за месяц, часы и смены, касса и штрафы, проверка перед закрытием месяца |
| `content` | Контент | `content` | черновики контент-плана, проверка недели, отзывы гостей |

Новый агент — файл `kultura_bot/agents/<имя>.md`:

```
---
name: supplies
title: Закупки
domains: stocks
description: Когда поручать задачу этому агенту — бот видит это в своих инструкциях.
---
Правила агента обычным текстом.
```

`name` — латиница, цифры, «_», 2–31 символ; `domains` — через запятую из `content`, `stocks`,
`analytics`, `staff`. Ошибка в заголовке называет файл, и тест `test_agents_and_prompts_load`
падает до выкладки.

### 6. Диалог и память

Диалог чата продолжается, пока выполнены все три условия:

- с прошлого вопроса прошло меньше `DIALOG_IDLE_MINUTES` = 120 минут;
- инструкции и инструменты те же: отпечаток = первые 16 символов sha256 от системного промпта и
  списка инструментов (`config.fingerprint`), он хранится с диалогом;
- история короче 3 МБ (каждый запрос отправляет её целиком).

Иначе — новый диалог, и ответ начинается пометкой: «Прошло много времени с прошлого вопроса,
начинаю новый диалог.» (`NEW_DIALOG_NOTICE`), «Обновились инструкции бота — начинаю новый
диалог.» или «Диалог стал слишком длинным — начинаю новый.». `/new` — новый диалог сразу.

История хранится в `bot_dialogs` (`mcp.db`) как есть. Ответ упал с ошибкой 400 (битая история) —
диалог стирается, человек получает «Диалог начат заново — повторите вопрос».

Выкладка перезапускает сервер и обрывает ответ на полпути: вопрос помечается `interrupted`, а
после запуска чат получает «Ответ на прошлый вопрос прервался: сервер перезапускался.
Повторите вопрос» — один раз на чат, если вопросу меньше 30 минут. Плановый перезапуск воркера
gunicorn (`--max-requests`) начатые ответы доводит до конца (не дольше таймаута воркера, 180 с), а
на вопрос, пришедший в эти секунды, бот отвечает «Сервер перезапускается — повторите вопрос через
минуту» (`RESTARTING_TEXT`): молча вопрос не теряется.

### 7. Деньги

Цена каждого шага модели (`claude.cost_usd`) — по токенам из `usage` ответа API:

```
цена шага ($) = (вход × P_вход + выход × P_выход + чтение_кэша × P_чтение + запись_кэша × P_запись) / 1 000 000
```

округляется до $0,000001. Цены за 1 млн токенов (`PRICES_PER_MTOK`, прайс Anthropic, октябрь
2026):

| Модель | Вход | Выход | Чтение кэша | Запись кэша (5 мин) |
|---|---|---|---|---|
| `claude-opus-5-5` | 4,00 | 20,00 | 0,20 | 5,00 |
| `claude-sonnet-5-5` | 2,00 | 10,00 | 0,20 | 2,50 |
| `claude-haiku-5-5` | 0,10 | 0,50 | 0,01 | 0,125 |
| `claude-opus-5`, `claude-opus-4-8` (запасные модели) | 5,00 | 25,00 | 0,50 | 6,25 |

Модель берётся из ответа (`response.model`): если ответила запасная модель, шаг считается по
её цене. Имя ищется по самому длинному совпавшему началу (`claude-opus-5-5-…` — не
`claude-opus-5`); модель не из таблицы считается по цене `MODEL`.

Пример (Opus 5.5): шаг с 3 000 новых токенов входа, 40 000 токенов из кэша и 600 токенами
ответа стоит (3 000 × 4 + 600 × 20 + 40 000 × 0,20) / 1 000 000 = (12 000 + 12 000 + 8 000) /
1 000 000 = $0,032. Вопрос в четыре шага — около $0,13.

Дневной предел `DAILY_BUDGET_USD` = $15: перед каждым шагом бот сверяет сумму за московские
сутки (`bot_usage`) с пределом; достигнут — в чат «Дневной предел расхода на Claude исчерпан:
X $ из 15 $… Бот снова ответит после полуночи МСК». Шаг, начатый до предела, доводится до конца,
поэтому предел может быть превышен на один шаг. `0` — без предела.

Расход копится в `bot_usage` по дням и моделям (запросы, токены, $); страница показывает
«сегодня» и «за 30 дней». Это оценка по токенам: источник истины — счёт в консоли Anthropic
(там же можно поставить свой предел расходов на ключ).

### 8. Состояние и ошибки

Бот пишет своё состояние в `settings` (`mcp.db`, ключ `kultura_bot_status`): опрос идёт в одном
воркере, а страницу может открыть другой. Страница показывает его первой строкой раздела.

| Состояние | Что на странице | Что делать |
|---|---|---|
| нет записи | «Бот не запущен: сервис его ещё не стартовал» | подождать минуту после выкладки |
| `starting` | «Бот запускается…» | — |
| `waiting` | «Бот ждёт настройки: нет токена бота / нет ключа Anthropic API» | вставить и сохранить |
| `paused` | «Бот на паузе» | снять флажок «Пауза» |
| `running` | «Бот @MCPkulturabot работает: слушает Telegram и отвечает» | — |
| `conflict` | «Конфликт: токеном бота пользуется другая программа (старый бот?)…» | остановить другую программу |
| `error` | текст ошибки: Telegram не принимает токен, нет связи с Telegram, ключ Anthropic не принят, отказ серверу (403), кончились деньги, нет связи с Anthropic | по тексту |
| давно не обновлялось (`running`/`conflict` старше 3 минут) | «Бот давно не отзывался…» | сервис перезапускается или упал |

Ошибки Anthropic человек получает понятным текстом (`claude.describe_error`):

| Ошибка | Текст (суть) |
|---|---|
| 401 | «Anthropic не принял ключ API» — новый ключ на странице |
| 403 | «Anthropic отказал серверу» — если сервер в стране, где API недоступен, нужен прокси |
| нет связи, таймаут | «Нет связи с Anthropic» — то же про прокси |
| 429 | «Anthropic ограничил частоту запросов» — повторить через минуту |
| 529 | «Claude сейчас перегружен» — повторить через пару минут |
| 5xx | «Сбой на стороне Anthropic» |
| мало денег на счёте | «На счёте Anthropic кончились деньги» — пополнить в консоли |
| другая 400 | текст ошибки + «Диалог начат заново — повторите вопрос» |

Токен, ключ и прокси в тексты ошибок для чата и страницы не попадают: всё, что пришло из
исключения, проходит `claude.scrub` — секреты, адрес прокси и пароль из него заменяются на «***».

### 9. Страница «Доступ агентов», раздел «Бот @MCPkulturabot»

| Поле | Что | Проверка при сохранении |
|---|---|---|
| Токен бота в Telegram | из @BotFather (`/mybots` -> бот -> API Token) | формат и `getMe` в Telegram: неверный не сохраняется, у верного запоминается имя бота; нет связи — сохраняется с предупреждением |
| Ключ Claude API (Anthropic) | console.anthropic.com -> API Keys -> Create Key | формат `sk-ant-…` и бесплатный запрос списка моделей тем же путём, каким пойдёт бот: 401 — не сохраняется; 403 и «нет связи» — сохраняется с подсказкой про прокси |
| Прокси для Anthropic | `http(s)://[логин:пароль@]хост:порт`, только если Anthropic не пускает сервер; «-» — убрать | только http(s) с хостом; новый прокси — повторная проверка ключа через него |
| Пауза | бот молчит (экстренная остановка); графики агентов по MCP при этом уходят | — |

Сначала проверяется всё, потом пишется: ошибка в одном поле не сохраняет другие. Пустое поле —
значение не меняется. На странице и в ответах API — только подсказки вида «1234…xyz» и адрес
прокси без логина и пароля.

Ниже — «Кто может писать боту» (кнопка «Подключить мой Telegram», таблица привязок с кнопкой
«Отключить»), строка расхода и свёрнутое «Как устроен бот».

API (только администратор сайта; агентам по MCP закрыто — исключение «доступом к себе» в
`core/mcp/tools/common.py`, агент не управляет доступом к себе):

| Маршрут | Что |
|---|---|
| `GET /api/admin/mcp/bot` | подсказки секретов, пауза, состояние, расход, предел, модель, усилие, привязки, агенты |
| `PUT /api/admin/mcp/bot` | поля `token`, `clear_token`, `anthropic_key`, `clear_anthropic_key`, `proxy`, `paused`; другое поле или не тот тип — 400; ответ — как у `GET` и `warnings` |
| `POST /api/admin/mcp/bot/link` | одноразовая ссылка привязки для текущего администратора: `code`, `url`, `expires_in_s` |
| `DELETE /api/admin/mcp/bot/links/<tg_user_id>` | снять привязку (только цифры) |

Где хранится — таблица `settings` в `mcp.db`:

| Ключ | Что |
|---|---|
| `tg_chart_bot_token` | токен бота (имя ключа — с первой версии, когда бот только присылал графики: сохранённый тогда токен работает дальше) |
| `tg_chart_bot_username` | имя бота из `getMe` |
| `kultura_bot_anthropic_key` | ключ Claude API |
| `kultura_bot_proxy` | прокси к Anthropic |
| `kultura_bot_paused` | пауза |
| `kultura_bot_status` | состояние бота (раздел 8) |

Запасной путь, если на странице пусто, — окружение: `TELEGRAM_MCP_BOT_TOKEN`,
`KULTURA_BOT_ANTHROPIC_KEY`, `KULTURA_BOT_PROXY`.

Таблицы бота в `mcp.db` (`store.py`): `bot_links` (Telegram -> администратор), `bot_link_codes`
(коды привязки), `bot_dialogs` (история чата), `bot_jobs` (вопросы в работе и отвеченные),
`bot_usage` (расход по дням и моделям).

### 10. Что сделать владельцу (один раз)

1. Остановить старую программу бота, если она ещё где-то работает с этим токеном. Иначе
   Telegram отдаёт сообщения то ей, то сайту, а на странице — «Конфликт».
2. Создать ключ Claude API: console.anthropic.com -> API Keys -> Create Key.
3. Открыть `https://beerkultura.ru/admin/mcp` -> «Бот @MCPkulturabot»: вставить ключ (и токен
   бота, если подсказка под полем говорит «Нет») -> «Сохранить». Сервис проверит ключ. Появилось
   «Anthropic отказал серверу (403)» или «Нет связи с Anthropic» — нужен прокси: вписать его
   адрес и сохранить ещё раз.
4. «Подключить мой Telegram» -> «Открыть Telegram и нажать «Старт»» -> «Старт». Бот ответит
   «Готово: вы подключены как …».
5. Задать боту вопрос. Другие администраторы подключаются так же, каждый со своего входа на сайт.

### Что сломается при неверной правке

- Править историю диалога (удалять или менять старые сообщения, переставлять блоки) или менять
  системный промпт и порядок инструментов посреди диалога — Claude отбросит рассуждения модели
  (или ответит 400), кэш перестанет работать: ответы хуже и дороже. Всё переменное — только в
  сообщении человека.
- Положить токен или ключ в `settings.py` или в любой файл репозитория — репозиторий публичный.
- Убрать flock в `service.start` — два воркера опрашивают Telegram одновременно: 409 и потерянные
  сообщения.
- Убрать проверку администратора в `access.actor_for` — бот ответит кому угодно данными владельца.
- Не подставлять `chat_id` в `common_chart_send` — модель по «команде» из данных отправит график в
  чужой чат.
- Убрать дневной предел — зациклившийся агент потратит деньги.
- Добавить инструмент сайта, которого у бота быть не должно, и не внести его в `HIDDEN_TOOLS` —
  бот его получит: у бота все инструменты реестра MCP.
