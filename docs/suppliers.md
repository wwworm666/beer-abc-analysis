# suppliers.md — Справочник поставщиков (`/suppliers`, `/api/suppliers/*`)

> Этап 3 редизайна страницы «Заказы и остатки»
> ([docs/planning/stocks-order-redesign-2026-09-10.md](planning/stocks-order-redesign-2026-09-10.md)).
> Срок и дни поставки, кратность и написания поставщиков редактируются из интерфейса;
> в коде остались только стартовые значения и умолчания.

## Что это

До 2026-09-11 поставщик на странице заказа был сырой строкой `category` из
номенклатуры iiko (три написания одного «МаркетБир» давали три группы), а сроки поставки
жили в коде (`SUPPLIER_PARAMS`: 13 кухонных поставщиков, все пивные по умолчанию).
Справочник даёт экрану «К заказу» ([stocks.md](stocks.md)) и заказам
([orders.md](orders.md)):

| Поле | Что задаёт | На что влияет |
|---|---|---|
| Имя | каноническое имя поставщика | заголовок группы на «К заказу», текст заказа, карточка черновика |
| Написания (aliases) | как эта же компания называется в `category` iiko | склейка групп; поиск без регистра, кавычек и лишних пробелов |
| Срок поставки (`lead_time_days`) | дней доставки от отправки заказа до приёмки (1..60; раньше следующего дня доставки поставка не приезжает) | ближайшая и следующая поставка, горизонт формулы |
| Дни доставки (`delivery_weekdays`) | по каким дням поставщик привозит (пн = 0; по умолчанию пн–пт) | то же; заказ в пятницу при доставке пн–пт приедет в понедельник |
| Кратность (`pack_size`) | упаковка для фасовки и кухни (1..10000) | рекомендация округляется вверх; кеги считаются в литрах без кратности |
| Самовывоз (`self_pickup`) | Метро, Лента | пометка в заголовке группы (список покупок, а не сообщение поставщику) |
| Минимальный заказ (`min_order_sum`) | сумма в рублях, дешевле которой поставщик заказ не принимает (0 — минимума нет, до 10 000 000) | рекомендации группы считаются на больший срок, пока не дотянут до минимума |
| Считать минимум (`min_order_scope`) | `bar` — на каждую доставку в бар (по умолчанию), `order` — на весь заказ по всем барам | что складывается при проверке минимума и добора |
| Заметка | свободный текст до 500 символов | только для людей |

Поставщик, которого в справочнике нет, получает умолчания (`DEFAULT_LEAD_TIME_DAYS` = 3,
кратность 1, пн–пт, минимума нет) и помечен на «К заказу» «(по умолчанию)». Канал заказа
(чат, сайт, телефон) и контакт отложены на самый конец по решению владельца: пока все в чате.

## Как работает

### Модель и файл

```
suppliers[name] = {name, aliases: [str], lead_time_days: int, delivery_weekdays: [0..6],
                   pack_size: int, self_pickup: bool, min_order_sum: int,
                   min_order_scope: 'bar' | 'order', note: str, updated_at, updated_by}
```

Чтение кэшируется по mtime файла; запись — `threading.Lock` + `portalocker` +
перечитывание внутри блокировки + атомарная запись (как у заказов). Чтение (доска,
список) при битом файле отдаёт стартовый набор, битую запись пропускает с сообщением в
лог и такой неполный результат не кэширует. Запись (`upsert`, `delete`, `add_alias`)
читает файл строго: нечитаемый файл или битая запись — `SupplierDirectoryUnavailable`,
API отвечает 503 `suppliers_unavailable`, файл не трогается (иначе одна правка стёрла бы
справочник или молча удалила чужую запись). Кэш по mtime хранится одним кортежем и
отдаёт глубокие копии: четыре потока воркера читают его без блокировки.

Стартовый набор (`SEED_SUPPLIERS`): 12 кухонных поставщиков со сроками из прежнего
кода и 9 пивных по категориям номенклатуры (`ООО Невский Синдикат`, `ООО Фёст`,
`ООО МаркетБир` с написаниями `ООО "МаркетБир"` и `Маркет бир`, `СПБ-Премиум`,
`Партнер ООО`, `БирИнсайдерс`, `ДримТим`, `ЕГАИС`, `ООО ТК Параллель`) со сроком 3 дня
до уточнения владельцем; без них 90 % позиций доски были «по умолчанию».

### Нормализация и разрешение имени

`normalize_name`: без регистра (`casefold`), без кавычек всех видов, включая типографские
(`" « » ' \` “ ” „ ‟ ‘ ’ ‚`), пробелы схлопнуты; завершающий `/` из пути API отрезается.
`DirectoryView.resolve(category)`:

1. пустая строка → «Без поставщика» (`NO_SUPPLIER`);
2. нормализованное имя совпало с именем поставщика → это имя;
3. совпало с написанием → каноническое имя владельца написания;
4. иначе строка `category` как есть (поставщик «по умолчанию»).

Имена и написания уникальны между поставщиками: нельзя завести имя, равное чужому
написанию, или написание, уже принадлежащее другому; своё имя из написаний убирается.
Первое совпадение при построении индекса побеждает (сначала имена, потом написания).

### Минимальный заказ (с 2026-09-14)

Владелец: «Я не могу заказывать по три пиццы в поставку: почти у каждого поставщика
минимальный заказ от 10 000 руб.». Рекомендация «заказать 3 шт на 900 руб.» такому
поставщику отправить нельзя, и управляющий каждый раз добирал заказ на глаз.

Минимум — это не отдельная логика «добить чем попало»: доска считает **всю группу
поставщика на один увеличенный горизонт**, пока сумма рекомендаций не дотянет до
минимума. Заказываем тот же товар, который и так расходится, — просто реже и крупнее;
доля каждой позиции остаётся пропорциональной её расходу, формула строки не меняется
(меняется только число дней). Подробности расчёта и границы — в
[stocks.md](stocks.md), раздел «Минимальный заказ поставщика».

Цена единицы для суммы берётся из `core/purchase_price.py`: последняя приходная
накладная iiko за окно (`sum / amount` по самой поздней дате, строки одного дня
складываются), иначе себестоимость остатка (`sum / amount` по `balance/stores` всей
сети), иначе цены нет — позиция в сумму не входит и подписана «без цены». По выгрузке
за 30 дней накладная есть у 265 из 566 продаваемых товаров, поэтому запасной источник
обязателен. Цена — наша закупочная оценка, а не прайс поставщика, поэтому в текст
заказа для чата она не попадает.

`min_order_scope` решает, что складывается: `bar` — позиции одного бара (у большинства
дистрибьюторов минимум на адрес доставки), `order` — весь заказ поставщику по всем
барам сразу; во втором случае доска учитывает и то, что коллеги уже набрали в другие
бары. Стартовый набор: 10 000 руб. «на бар» у всех, кроме самовывоза (Метро, Лента) —
со слов владельца; уточняется по каждому поставщику здесь же.

### Как параметры попадают в формулу

На доске `order-board` срез справочника берётся один раз на запрос
(`get_supplier_directory().view()`), для каждой позиции `_supplier_params(category, view)`
даёт `name, lead_time_days, pack_size, delivery_weekdays, self_pickup, is_default`, а
`_delivery_plan(today, params)` — ближайшую и следующую поставку:

```
first_delivery   = next_delivery_date(today, lead_time_days, delivery_weekdays)
next_delivery    = delivery_after(first_delivery, delivery_weekdays)
days_to_delivery = first_delivery − today       (срочность)
horizon_days     = next_delivery − today        (формула «нужно»)
```

Пример. Среда, срок 2, доставка пн–пт: ближайшая пятница (2 дня), следующая понедельник
(5 дней) → нужно расход × (5 + 3). Тот же поставщик с доставкой только по понедельникам и
сроком 1: ближайшая понедельник (5 дней), следующая через неделю (12 дней).

### API

| Метод и путь | Тело | Ответ | Ошибки |
|---|---|---|---|
| `GET /api/suppliers` | — | `{suppliers[], unmapped_categories[{category, products}], nomenclature_available, defaults, stored}` | — |
| `PUT /api/suppliers/<name>` | `{aliases?, lead_time_days?, delivery_weekdays?, pack_size?, self_pickup?, min_order_sum?, min_order_scope?, note?, rename_to?}` — только переданные поля меняются, `null` = не передано; `self_pickup` принимает и строки `true/false/да/нет` | как GET + `supplier`; при переименовании ещё `orders_renamed` (сколько черновиков и заказов переехало) или `warning`, если файл заказов недоступен | 400 с текстом проверки («Срок поставки: от 1 до 60», «Написание … уже принадлежит …», «Имя … уже занято»); 503 `suppliers_unavailable` |
| `DELETE /api/suppliers/<name>` | — | как GET | 404; 503 |
| `POST /api/suppliers/<name>/aliases` | `{alias}` — слияние со списком под блокировкой (два управляющих не теряют написания друг друга) | как GET + `supplier` | 400, 404; 503 |

Переименование (`rename_to`): старое имя автоматически становится написанием (категория
iiko, из которой поставщик заведён, не отваливается в «по умолчанию»), черновики и
заказы в `orders.json` переезжают под новое имя (`OrderStore.rename_supplier`),
переименовать в чужое имя или написание нельзя, смена только регистра или кавычек —
та же запись, а не дубликат.

`unmapped_categories` — категории товаров `GOODS`/`PREPARED` из текущей номенклатуры
(`get_stocks_nomenclature`), которые ни к кому не привязаны, по убыванию числа товаров;
без iiko список пуст и `nomenclature_available = false`. Имя в пути ищется без учёта
регистра и кавычек.

### Страница `/suppliers`

Карточка на поставщика: написания через запятую, срок, кратность, минимальный заказ и
способ его счёта («на каждый бар» / «на весь заказ»), чекбоксы дней доставки,
самовывоз, заметка; «Сохранить», «Переименовать» (написания и старое имя сохраняются,
заказы переезжают), «Удалить». Несохранённые правки в других карточках переживают
сохранение соседней (помечены «Есть несохранённые правки»). Страница есть в боковом меню
(«Поставщики») и по кнопке на «К заказу».
Ошибка проверки показывается строкой в карточке. Поле «Имя нового поставщика» + «Добавить
поставщика». Блок «Категории iiko без поставщика»: для каждой — выпадающий список
«Привязать» как написание к существующему или «Завести как поставщика» с этим именем.
Ссылка «настроить» в заголовке каждой группы на «К заказу» ведёт сюда.
