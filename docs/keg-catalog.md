# Полный реестр кег и использование за два года

## Что это

Выгрузка живой номенклатуры iiko и складской истории по запросу владельца.
Снимок от 20.09.2026: **479 внутренних товарных карточек кег**, из них
**461 актуальная, 1 в архивной группе и 17 удалённых**.
Это количество карточек (GUID), не физических кег и не уникальных сортов.

За период **20.09.2024–20.09.2026 включительно** движение есть у
**233 карточек**, все они сейчас актуальные. У **226** есть складское списание
по продажам, ещё у **7** — только другие складские операции.
У 228 актуальных карточек движения в выбранном периоде не найдено.
Статус «актуальная» относится к справочнику, не к наличию остатка сегодня.

## Файлы

- `scripts/export_keg_catalog.py` — чтение API, классификация и JSON/CSV;
  использует стандартную библиотеку Python.
- `output/kegs-2026-09-20/kegs-iiko-2026-09-20.xlsx` — результат:
  «Все кеги», «Использовались 2 года», «Методика».
- `output/kegs-2026-09-20/keg-register.json` — карточки, показатели,
  определения, контрольные количества и описание колонок.
- `output/kegs-2026-09-20/all-kegs.csv`, `used-kegs-2-years.csv` — списки
  UTF-8 с BOM, разделитель `;`.
- `output/kegs-2026-09-20/source-*.json` — исходные справочники, запросы и
  ответы интервалов; manifest содержит SHA-256 и время чтения.
- `output/kegs-2026-09-20/build-kegs.mjs` — оформление Excel через Artifact Tool.

## Как работает (с примерами и формулами)

### Каталог

Использованы `/resto/api/v2/entities/products/list`,
`/v2/entities/products/group/list`, `/v2/entities/list?rootType=MeasureUnit`.
Везде `includeDeleted=true`. Получены 9110 товаров, 189 групп, 4 единицы.
Иерархия построена по `parent` GUID, единица разрешена из `mainUnit`.

Включается внутренний складской товар `type=GOODS`, если:

1. Единица — литры, а в цепочке родителей есть группа кег, либо в карточке
   есть кеговая фасовка `containers.name`, либо название явно содержит КЕГ/keg.
2. Либо единица — штуки, а название явно задаёт «пиво … кег».
   Объём в литры автоматически не переводится.

Группа `Kеги` (первая буква латинская) имеет GUID
`4a5b2a76-8f86-4365-b8e6-5c9aeecd3323`, родитель — «Напитки Розлив».
GUID закреплён в скрипте как идентификатор именно этой базы iiko.
В группе 464 литровых товара: 461 актуальный и 3 удалённых.
Ещё 13 удалённых литровых карточек находятся вне группы разлива;
кеговая фасовка подтверждена `containers`. Среди них карточка «1», артикул
`00019`: фасовка «кег», 30 л есть, название сорта не установлено — отмечено отдельно.

Ещё две карточки учитываются в штуках: удалённая «КОНИКС МЮНИХ ХЕЛЛЕС»
и «ФХ Хеллес» в «Архив товаров». У обеих `unitCapacity=0` и нет фасовок.
Число 30 из названия не использовано как коэффициент перевода.

Статус: сначала `deleted=true` → «Удалена»; иначе предок «Архив товаров»
(`14bc1f9d-e172-1a9d-0196-f2627515aab6`) или «Архив»
(`be375ee4-671f-4c7b-87ae-ab945b1f8edc`) → «В архиве»; иначе «Актуальная».

Порции `DISH`, товары поставщиков `OUTER`, оливки в кеге, газовая смесь,
масла, молоко и банки не включаются. Фильтр «Напитки Розлив + литры»
без типа товара добавил бы 781 порционное блюдо. Правило проверено на этом
снимке; для чужой базы или новых способов учёта нужно проверять исключения заново.

### История и формулы

Read-only `POST /resto/api/v2/reports/olap`, `reportType=TRANSACTIONS`.
Поля сверены с живым `/olap/columns`. 25 последовательных непересекающихся
интервалов покрывают `[2024-09-20, 2026-09-21)`, правая граница исключена.
Последний день содержит проведённые к моменту чтения операции.

История запрошена для широкой группы кандидатов: все `GOODS` в литрах
и `GOODS` со словом «кег» в имени, затем соединена с реестром по `Product.Id`.
Все 479 GUID входят в запросы. Ограничения по текущей верхней группе нет:
архивный товар мог быть перенесён.
Фильтры: `Account.StoreOrAccount=STORE`, `TransactionType != OPENING_BALANCE`.
Бухгалтерские коррсчета и начальные остатки исключены. Все четыре склада:
Большой пр. В.О, Варшавская, Кременчугская, Лиговский. У каждого есть данные
за 20.09.2026. Первое движение Лиговского в ответах — 03.09.2025.

Группировка: день, GUID/имя/артикул/тип/единица товара, склад, тип операции.
29488 исходных строк = 28468 ненулевых строк кег + 818 ненулевых не-кег
(масло, молоко, Lapochka) + 202 нулевые строки. Строка OLAP не равна документу.

```text
Использовался = существует строка: Amount.In != 0 ИЛИ Amount.Out != 0
Списывался по продажам = существует строка:
    TransactionType = SESSION_WRITEOFF И Amount.Out != 0
Приход = сумма Amount.In всех строк
Списание по продажам = сумма Amount.Out строк SESSION_WRITEOFF
Прочий расход = сумма Amount.Out остальных типов
Первое/последнее движение = min/max даты ненулевых строк в периоде
```

Например, приход 30 л и расход 30 л дают нулевое нетто, но товар использовался.
Поэтому фильтр по остатку или нетто `Amount` не применяется. Приход без продажи
тоже включается. Перемещение входит в приход одного склада и расход другого,
но GUID учитывается один раз; объём перемещений не объявляется продажами.

Количества сохраняются в базовой единице, со знаками iiko. Суммы через
`Decimal(str(value))`, без промежуточного округления; в JSON/Excel — числа.
Excel отображает три знака после запятой, что не меняет хранимое число.
Штуки и литры не суммируются вместе. Похожие названия не объединяются:
один GUID — одна строка. GUID и артикулы в Excel текстовые.

### Повторение и проверки

Из корня репозитория, с Python 3 и `.env` проекта:

```text
python scripts/export_keg_catalog.py --phase catalog
python scripts/export_keg_catalog.py --phase usage --from-date 2024-09-20 --through-date 2026-09-20
python scripts/export_keg_catalog.py --phase export
```

`--output <папка>` задаёт другой каталог. Для нового снимка использовать
новую папку во всех трёх фазах. По умолчанию зафиксированы дата и папка
этого экспорта; «два года» не вычисляются относительно дня повторного запуска.
Сохранённые ответы переиспользуются только при совпадении запроса;
`--refresh` перечитывает историю, включая текущий неполный месяц.

Экспорт отклоняется при неполной загрузке интервалов, изменении контрольных
сумм/запроса, нарушении дат, повторном GUID, неизвестной/циклической иерархии
либо несогласованной единице истории и карточки. Независимо пересчитаны
все итоговые количества, GUID, статусы, даты, признаки и суммы по исходным ответам.
Проверены отсутствие дыр/перекрытий дат и контрольные суммы файлов.
В сохранённом XLSX сверены 9476 ячеек с JSON, текстовые GUID/артикулы,
числовые сортируемые даты (`yyyy-mm-dd`), фильтры и закрепление 2 столбцов
и 6 строк. Формульных ошибок нет; просмотрены рендеры всех трёх листов,
включая правые колонки с объёмами и примечаниями.

Авторизация использует локальные `IIKO_SERVER`, `IIKO_PORT`, `IIKO_LOGIN`,
`IIKO_PASSWORD`; секреты и токен не выводятся и не записываются в результаты.
В конце сессии `/logout` освобождает слот лицензии. Записей в iiko нет.
